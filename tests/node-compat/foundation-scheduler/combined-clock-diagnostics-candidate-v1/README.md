# Private combined clock diagnostics: uncompiled source template

This is a separate, unapplied diagnostic variant proposal. **Current combined355 engine355550/full80-field sidecar5f3be and its stage/freeze are unchanged and do not expose this module, snapshots or counters.** No compiler, configure, build, native helper, componentizer, engine, guest, clock, host, reset, DEBUG, OOM, GC-pressure or CryptoKey operation ran in preparation. New C++ has not received an SDK syntax check or link test. The source/data and pure model results are not native execution evidence.

The explicit proposed inventory is357 native files: the355 parent paths, with four afterimages, plus a private header and builtin CPP. The changed native files are runtime/event_loop.cpp, builtins/web/timers.cpp, host-apis/wasi-0.2.0/host_api.cpp and cmake/builtins.cmake. External embedding/embedding.cpp changes separately; the external embedding partition still has three paths. All remaining351 parent native paths and two embedding paths retain their parent bytes. The exact source-origin inventory is in proposed-source-inventory.json; it is future build input DATA, not emitted metadata or a source admission.

Both `NODE_COMPAT_LIFECYCLE_DIAGNOSTICS` and `ENABLE_BUILTIN_DIAGNOSTICS_CLOCK_LIFECYCLE` are OFF by default. Enabling either without the other refuses. Enabled construction requires real Node/timer targets and ordinary Release without debugger/OOM/GC-stress. Existing add_builtin links the private target to extension_api/SpiderMonkey and adds its actual install namespace. The instrumentation macro propagates through the genuine extension_api interface and explicitly to host_api. No old helper, module globals, Source index, metadata count or Root state is rebound. A real new producer/policy/admission/recipe and full rebuild are still absent and required; the target/CMake/model/Source inventory must be observed genuinely. The forecast is one extra CPP (63 policy CPP/69 DB if the parent's62/68 layout otherwise holds); strict/private partitions must be freshly classified, never copied from the old4/6 labels.

The private native module `starling:test-clock-lifecycle` exports only `snapshot()` and its default record. It returns copies of native data, with all u64 values encoded as complete decimal strings. There is no setter, scheduling/cancel/reset function, host service or public Node/global export. Capturing the native POD precedes JS allocations used for serialization. The ledger has no task pointer/RefPtr/JS edge and creates no extra task root. Its fixed512 lease rows never wrap/reuse: overflow is sticky; `recordingComplete` becomes false and the pure future collector rejects it. An invariant failure is likewise sticky and rejected. The diagnostic hooks do not repair, reset, cancel or force success in the code they observe.

Instrumentation covers real TimerTask construction/retirement/destruction, every acquired timer pollable and its existing invalidate-before-drop path, standard MonotonicClock unsubscribe attempt/return, queue enqueue/detach/prune, selector empty/poll counts, cached immediate pollable acquisition/use and actual interest increments/decrements. Per-timer leases have unique internal serials distinct from potentially recycled WASI handle numbers; native handle values remain private and are not returned. Current queue length, interest, loop-running flag, timer-registry size and cached ownership are read directly from the genuine owning structures. Snapshots also retain the last real event-loop return and post_call/free-list boundary, tagged with the completed call serial/function index. A snapshot taken inside a new export sees that export's own interest; `requirePreviousTimerBoundary` checks the prior completed boundary instead of asserting current interest zero.

The diagnostic fixture has a **new four-export WIT**: original inspect/run(u32)/validate plus snapshot()->string. It reexports the original seven-case resource module unchanged and imports the private native observer into the SAME component/linear memory. A separate observer component would inspect a different instance and cannot be used for these assertions. Future bundling must explicitly admit/externalize the private specifier alongside native node:buffer; the existing public eleven-manifest profile is not silently expanded here. Native/packaging/source/component/type-graph/loading proof must be new. Standard host capability selection stays exactly clocks wall+monotonic and io/poll@0.2.10; actual emission must prove that, with no automatic widening. No package loader or runner is included in this packet.

`validate-snapshot.mjs` validates an already-durable whole scalar string and fails on incomplete ledger data, counter imbalance, illegal ordering, unknown fields, reused/missing leases or invented host-table observations. Its previous-boundary helper deliberately permits a separately reported still-owned immediate cache; that is timer-boundary evidence, not full native disposal. No arithmetic or return label can promote it to a host Store or reuse proof. The pure tests exercise counter/lease/ordering/overflow and prior/current boundary distinctions; they do not execute these C++ hooks.

The native binding's pollable drop is a void imported resource-drop call. Rust splicer stubs/type rewriting and the standard host's resource store are different layers. Instrumenting before/after the C++ call proves at most that this call returned. It cannot observe the host resource table, actual Store death, destructor execution at process disposal, freed bytes, or absence of hidden host references. No Rust/host implementation is modified. The current cached immediate pollable still has no explicit native teardown/drop path; this proposal observes and reports ownership without adding cleanup. Fatal/trapped instances may never return a final snapshot; their terminal/group cleanup is not a post-failure native resource receipt. Full failure-path drop accounting remains unresolved. No raw memory inspection or custom host provider is introduced.

Remaining gates include SDK grammar/type checks of the actual new CPP/header with a real VFS overlay and current target flags; full configure/registration/source policy; fresh ABI-dependent rebuild/link and ODR state identity; actual component four-export ABI/import/core graph; same-instance raw observations around all seven cases; bounded private invalid/survivor task fixtures; and an explicit cached-resource/closing/teardown design if full disposal is required. This read-only module does not create the missing task fixture or make unsafe Engine::reset, HTTP/stream cancellation, request cleanup, owner epochs, ALS, adoption or security/performance acceptance safe.
