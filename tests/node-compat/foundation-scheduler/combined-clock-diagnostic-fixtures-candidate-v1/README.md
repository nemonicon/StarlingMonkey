## Real missing APIs — fail closed

**All-invalid selector setup is absent.** `TimerTask::clear` calls `Engine::cancel_async_task`; the real queue erases the task before `retire()` invalidates/drops its pollable. Thus successful clearTimeout/double-clear/cancelledCallbacks0 does not create a queue containing invalid tasks. The survivor fixture proves ordinary progress and detach-cancel counts, not the `prunedInvalid`/`selectorEmpty` branch. `requireAllInvalidEvidence` rejects those unchanged counters and never grants the full gate even for a synthetic positive observation.

The relevant actual seams are `api::AsyncTask::handle_` / `id()` / `select(vector<RefPtr<AsyncTask>>&)` in the parent extension API, the static owning `queue` and `EventLoop::queue_async_task` in event_loop.cpp, and the invalid erase / empty-nullopt in host_api.cpp. There is no exported setter, queue accessor, test-task constructor or native settlement API in7aed. A future private default-OFF synchronous selector probe could check the actual Engine queue is empty/inactive, enqueue a bounded invalid task cut through the real queue API, then call the real selector once on that actual queue and retain real prune/drop/interest deltas. It needs a genuine new accessor in the owning translation unit and explicit source/counter ownership checks; a private local-vector stand-in is not equivalent. It would test a synchronous native selector branch, **not natural event-loop promise settlement or teardown**.

Simply arming invalid tasks from async JS is insufficient: a fulfilled export may end interest before selection, while a promise left pending after all tasks prune reaches interest>0/queue-empty failure on the next loop. No fake JS Promise/timer approximation is included here. A natural-loop test would require a separate safe bounded settlement design.

**Native offset is absent.** Actual runtime/js.cpp owns static `mono_clock_offset`, applies it in `clock_gettime(CLOCK_MONOTONIC)`, and updates it via max(offset,t) in `wizen()`. The separately linked embedding initializes `Performance::timeOrigin` on its first deployed call; performance.cpp returns float32 duration/origin values. Snapshot exposes none of these native symbols, source clock IDs, raw timestamps or transition counts. A real read-only accessor in the owning unit plus genuine wizer/embedding transition evidence is needed before claiming offset/resumption semantics. Adding guessed fields to today's snapshot is rejected by the exact schema. Source references bind the actual frozen parent files, not merely a similarly named workspace copy.

**Host Store death, fatal cleanup and cached drop remain unobservable.** Timer-drop-returned counts mark a C++ imported drop call returning; they are not host resource-table destruction, freed bytes, Store death or post-trap final accounting. The immediate cache has no explicit teardown/drop path in7aed. A trapped instance may never return another snapshot. No fatal guest or unsafe same-instance reset is added to manufacture evidence.
