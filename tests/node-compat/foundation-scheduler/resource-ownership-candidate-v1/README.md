The timer registry now owns RefPtrs and traces callback/argument edges until explicit retirement. Argument storage and timer/map allocation are checked before the existing void queue commit and first host subscription. One idempotent retirement path invalidates and drops the owned pollable, removes its registry row and clears saved JS edges on success, ordinary callback throw, argv allocation failure, queued/running clear and repeat cancellation. Running clear no longer relies on finding the timer in the queue. The destructor has a pollable-drop backstop. IDs remain bounded positive int32 values and are not rewound by timer-only cleanup.

The event loop locally roots the actual task, with its trace method, before detaching it for run/cancel. Cancellation copies the target before erasing a possibly aliased constRefPtr vector element. These are actual pinned Rooted/StructGCPolicy APIs; a native RefPtr alone would not trace callback edges. The change preserves the old cancel API result convention and does not turn every task subclass into a cancellable resource.

The global queue remains the existing void std::vector::emplace_back API. Its native allocation failure has no recoverable status and is outside this candidate's recoverable transaction claim.
