This candidate proposes a real native `runInNewContext`: a distinct SpiderMonkey147 global/realm in the existing engine compartment, ordinary native compilation and script execution, and explicit finite-data copying. It is **uncompiled Source**, not a deployed VM or a Next Wasm result. No SDK/compiler, native producer, engine or guest ran for this candidate. The only executions were authorized Node22 metadata/data-model tests.

The actual Next16.4.5 `load-manifest.external.js:68–102` reads JavaScript and calls `vm.runInNewContext(content, contextObject)`, then freezes/caches/returns that same supplied object. A return-only parser would not implement this. All19 current client-reference manifests (65,070 bytes,372–5,742 each) match their current original standalone counterparts. Its rooted global, input, completion, descriptors, key vectors and copier object/value vectors cover GC edges. Native `JS::Compile` plus `JS_ExecuteScript` execute the actual source. ScriptPrivate holds the data-realm global so the ordinary module loader can reject dynamic import before builtin lookup or filesystem access. A native RAII guard restores an original throw if later materialization fails. Copy-out failure also cannot turn a thrown public call into success.
