This is an isolated UNCOMPILED Buffer.concat Source proposal. Production files and existing engines/results remain unchanged. It promotes the existing concat constructor-property slot and adds no new host import, public export name, native source path or CMake flag. The five afterimages are buffer.cpp, buffer-facade.mjs, factories.generated.h, generate-factories.mjs and the exact core manifest. A future genuine integration must regenerate its source inventory/metadata and obtain independent review before any native build or guest use.

The pinned Node22.14 executable supplied its own primary lib/buffer.js Source through process.binding('natives').buffer; that whole Source and capture argv are retained. Its concat implementation validates Array, ignores totalLength for an empty list, derives omitted totals, validates all entries even after truncation and zero-fills a longer requested output. Differential tests use that real Node Buffer implementation. Error name/code matches are checked for the ordinary invalid forms; detailed Node messages/allocation order are not claimed.

Supported inputs are a dense Array of own data entries containing fixed Buffer/Uint8Array views, including nonzero offsets, repeated/empty views and ordinary Uint8Array subclasses. Optional length is a nonnegative integer. Empty lists ignore any supplied length. Output and each visible input are limited to16MiB, with at most65536 chunks. Omitted totals use checked subtraction before addition. Explicit lengths may truncate or zero-pad; invalid later entries still refuse when the requested length is zero/full. Output always copies and uses fresh exact fixed backing at offset0, independent of poolSize or user replacement of allocUnsafe.

The facade uses captured intrinsic metadata getters and snapshots view references into inaccessible own data properties before calling the private native kernel. Sparse/accessor lists, own shadowed typed metadata and shared/resizable/detached backing explicitly refuse. Proxy/custom prototype/getter timing, side effects, Node slab allocation and caller-replaced allocUnsafe behavior are outside the contract. The four previous unsupported/error paths are not silently relabeled as supported.

The genuine native kernel revalidates types and fixed backing, roots every source in RootedObjectVector, allocates/root the fresh result, then rechecks backing after possible moving GC. Metadata probe pointers are ignored. Only inside AutoCheckCannotGC does it reacquire visible Uint8Array pointers and run zero-fill/memcpy; no JS property access/allocation/callback occurs during the borrow. Every copy length is clipped to remaining destination bytes, so position never exceeds length. Zero-length pointers are never passed to memset/memcpy. No staging allocation or native pointer survives the call. These are reviewed Source properties, not a compiled GC/finalizer/runtime proof.

The actual existing generator was derived with a small explicit --core-only mode for this isolated packaging directory. Normal default/check execution keeps every optional generator in its original context. The core header is genuinely regenerated and its Buffer factory is evaluated in a host-only test. Unchanged unsupported/child-process/schema/validator files are copied as labeled packaging dependencies, not new native changes. The new m0.18 manifest removes only concat from unsupportedStatic and declares its finite overloads/deviations; all other methods, child-process errors and export/default bindings retain their prior scope.

Host tests instantiate the actual facade and generated factory with a clearly TEST-ONLY JavaScript byte-copy kernel, compare real Node results, and check limits/refusals/copy isolation. They do not execute the C++ kernel, a Wasm engine, a guest or Next. The 16MiB boundary test is a finite allocation check, not GC/OOM pressure or a cost measurement. No SDK frontend, native build, linker, explicit collection, fault/reset or key/crypto action ran. Existing ENABLE_BUILTIN_NODE_COMPAT selects the core; this work authorizes no instrumented GC/OOM build or security/adoption claim.
