# Bounded six-sync codec cost SOURCE proposal

This is a concrete, unexecuted comparison design with source templates. It installs no module, opens no350 operational admission, invokes no codec or library, produces no bundle/component/oracle, and authorizes no native, guest, host, pilot or timing work. Future pair/action/correctness pins remain NULL. Foundations-v13 classic acceptance does not accept zlib350 or consumers355. Current metadata, operational admission and held old contexts are unchanged.

Pinned fflate0.8.3's **explicit browser ESM** is a new proposed comparand. Installed tooling is not evidence that it runs in a guest. The six mapping entries in `protocol.json` use zlibSync/unzlibSync, gzipSync/gunzipSync and raw deflateSync/inflateSync. The native facade accepts no level option: its only admitted optional key is maxOutputLength, so this design calls native with input only/default limit. fflate uses private fixed level6 and gzipmtime0, no filename/dictionary/out/consume. Those are internal comparison settings, not newly accepted public options. Encoded byte identity is never required.

The original Jco zlib adapter imports custom `jco:node/zlib@0.1.0`; it is not a portable baseline and is excluded. Node22.14 is an external untimed correctness oracle, not a guest performance arm. Provider source is not patched and no scheduler, process, Worker, Date, Blob or global proxy is substituted.

## Finite common domain

Five deterministic raw fixtures cover empty,64-byte repeated/PRNG and512KiB repeated/PRNG data. Six operation IDs produce30 primary cases. The PRNG label describes a fixed xorshift32 byte sequence, not proven statistical incompressibility or entropy. Fixture hashes/FNV are prepared with a pure Python equivalent, not by a codec.512KiB provides headroom but is not proof that an encoding fits1MiB. Every actual Node/native/fflate stream must pass the1MiB compressed-input gate before any decoder sees it; all outputs must fit16MiB and match the expected raw fixture. Native encoding of a full1MiB incompressible input is deliberately outside this proposal.

Require fixed, attached, unshared ordinary input windows with sentinels before/after; no dictionaries, trailing bytes, concatenated members, alternate encodings, malformed data, async APIs or streaming codecs. Node produces the common decode inputs. Future untimed correctness records45 actual encoder outputs (three encoders ×three formats ×five fixtures), full decoded byte equality on135 cross-decoder edges, compressed lengths/hashes and raw output bytes. Validate native/fflate decoded Node streams and Node-decode every provider encoding. Keep any discrepancy before timing. gzip is one member only; final framing/trailer/checksum checks and determinism must be proved on actual bytes, not inferred from names.

The trusted valid corpus has at most512KiB decoded output. The fflate wrapper only checks output length **after** allocation; it is not equivalent to native's enforced output cap and supplies no malformed-data/resource-limit/error parity. Cross-decode proof does not broaden the released surface. Future components must reproduce correctness over three retained rotations plus freshJco/freshWasmtime, no forcedGC/reset. Both first/fresh and retained-instance results need explicit public call counters, nonempty input/output non-aliasing, output independence across successive calls and mutation probes. Empty backing-object identity is recorded without inventing addressable-byte isolation. Snapshot state may contain only input fixture bytes, code and immutable lookup data; no pre-run codec output, pending callback, stream or resource.

## Comparisons and costs

Use three separately reported arms: native-ON and browserFF-ON on the exact same genuine350 normal-OFF engine; then identical browserFF bundle bytes on ON and disabled-OFF engines. The second comparison measures unused profile/startup/size/RSS cost and must not be merged into codec speed claims. Existing fb1656/3d1953 frozen facts are data references only, not cost-pair authority. Do not transform350 into355 or pretend old metadata's backend/operational-proof fields changed.

Setup constructs one owned native Buffer outside timed operation samples. Timed work calls the whole selected provider and consumes every output byte through the same onlineFNV loop. Native input staging, malloc/realloc and native-to-JS output copying remain included; browserFF reads guest input and allocates JS output. Both wrappers return a Buffer sharing the provider's fresh JS-owned output window. Do not add/remove an artificial codec copy to manufacture equality. Include separate construction/copy/consume controls and their FNV work as raw observations, never subtractions. Full byte/cross-decode checks are untimed; compact per-batch checksums/counters remain timed and are saved before assertion. Encoder signatures are provider-specific validated actual results; decoder expected bytes are common. No output arrays or per-byte number traces are retained across iterations.

Throughput uses original logical **uncompressed** bytes per operation for encode and decode. Persist actual compressed input/output lengths and encoded/raw ratios separately. Empty fixtures have zero logical bytes and report operations/second with null byte-throughput and null compressed/raw ratio, never division by zero. `protocol.json` fixes the finite sample/order/budget proposal. Three fresh processes per arm/comparison, AB/BA/AB, are the independent units; seven within-process samples are correlated. No universal win, guest heap/capacity/grow counts or physically cold startup is inferred.
