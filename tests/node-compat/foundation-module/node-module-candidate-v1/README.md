This is an isolated, UNCOMPILED/UNAPPLIED node:module Source candidate for the real Next.js loader path. It does not change production, configured sources, engines or accepted profile pins. It implements synchronous POSIX CommonJS and JSON rather than replacing Next with an SSR subset. The native backend, CMake branch and generated header have not been compiled, linked, componentized or run in a guest.

The guest core implements the Module constructor, prototype.require/load/_compile, mutable _resolveFilename/_resolveLookupPaths/_nodeModulePaths/_load, createRequire, require.resolve/cache/extensions, package main and finite require/node/default export conditions/patterns, JSON, realpath identity, cycles and failed-load eviction. It inserts the actual Module object before evaluating its body. A per-module require calls the current prototype.require; _load calls the current _resolveFilename. Next's actual require-hook can therefore interpose on those genuine methods. CommonJS exports and cache live entirely in ordinary GC-traced JS objects/closures. No native map hides untraced JS pointers, no global require is injected, and no Proxy is introduced.

The new private C++ provider uses the pinned JSAPI147 CompileFunction with the five real CJS arguments and an empty, rooted EnvironmentChain. It returns an actual compiled JS function; the guest core calls it with this===module.exports. Source/filename byte buffers remain owned during compilation, returned functions/values use JS::Rooted handles, and FILE handles close on every path before a module value is returned. Read/regular-file-size limits apply before allocation. No FILE, fd or compiler buffer is persisted in this provider. All filesystem primitives require BOTH EngineInitialized and the real deployed-entry bit BEFORE path encoding or any libc access; pure native builtin lookup and JS compilation can remain during INIT. The new unconditional read-only accessor observes the existing entropy TU bit without changing its real entry setter. This prevents initial Wizer execution from populating libc preopen caches via this provider. It does not admit re-snapshotting a deployed instance or establish libc cached-descriptor safety across any future reset/reuse. The new ScriptLoader lookup uses its existing PersistentRooted builtin map and returns an installed record's real default binding, preserving bare/prefixed CJS value identity without cloning a namespace or providing a JS builtin adapter. It is an explicit NEW private guest API, not an existing embedding or host service.

The filesystem primitives use genuine guest libc stat/fstat/fopen/read/realpath/getcwd. Their SDK declarations are retained as hashed inputs. Future standard WASI filesystem preopens/rights, cwd agreement with process, libc runtime behavior, emitted interfaces, limits, symlinks and errors require actual validation. The planned general FS provider may replace these four private IO primitives with its genuine direct-P2 descriptor walker in a separate successor; no invented reader API is used here.
