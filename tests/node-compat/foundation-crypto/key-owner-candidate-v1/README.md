Raw and JWK import allocations adopt that deleter immediately. Published HMAC spans borrow `owner->data()/owner->size()` from the rooted key; no raw HMAC bytes, optional bit-length rules or cryptographic operation bodies change. KeyDataLength remains an unused reserved slot to preserve the private layout; its former int32 conversion is no longer the span-size authority.

CryptoKey gets a local foreground policy and independently clears/frees its Key and KeyData slots. Undefined owners, including the prototype and failed partial object construction, are harmless. The finalizer reads no Algorithm or Type and makes no JS allocation/callback. All fallible JS work still precedes ownership publication. Each EVP_PKEY has its existing unique owner before transfer, then the key slot owns its single reference until finalization. A native vector contains no GC edges, so no new trace hook is appropriate.
