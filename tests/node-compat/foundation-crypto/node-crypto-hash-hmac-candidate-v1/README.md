# Uncompiled Node SHA256 Hash/Hmac proposal

This packet proposes a small synchronous `node:crypto` / `crypto` slice for the actual Next fixture's `createHash('sha256').update(text).digest('hex')`. It contains an executable JavaScript facade, an **uncompiled** guest EVP kernel, and unapplied CMake/registration afterimages against the unchanged combined355 staged source. It is not a native artifact, an activated module, or evidence that Next.js works. The fixture also uses filesystem APIs.

`crypto-facade.mjs` provides only SHA256 `createHash` / `createHmac`, synchronous `update`, and `digest` returning a Buffer or lowercase hex. Inputs are UTF8 strings up to 1 Mi code units or fixed nonshared Uint8Array/Buffer windows; messages are at most 16 MiB per update and 64 MiB cumulatively, keys at most 1 MiB. Empty keys/messages work in the proposed protocol. Strings go through the captured installed Buffer UTF8 conversion once. Key staging created for strings is wiped in `finally`; caller-owned buffers and original strings are not erased.

`node-export-manifest.json` describes the complete initial **Node v22.14.0** export-name surface derived from the captured official sources, rather than executing Node crypto. Of 68 ESM names including default, only the two factories implement new operations in this profile. `Hash` and `Hmac` are factory-result prototypes with refusing public constructors. Other callable names throw `ERR_SM_NODE_UNSUPPORTED`. `constants` is a meaningful frozen numeric object with nine names selected from official Node constants and **actual guest OpenSSL headers**, not a blank object or a fabricated cipher list. `constants-policy.json` records the partial set and backend-version distinction: header-derived version 3.0.17 is not host Node's backend version, runtime attestation, or cipher availability proof. All omitted TLS/cipher/ENGINE/DH/EC constants remain explicit gaps. `webcrypto` and `subtle` reuse the actual existing native global Crypto and its SubtleCrypto object, rather than an undefined placeholder or replacement implementation. Their inherited implementation limits remain in effect; actual alias identity validation is still a future gate.

The default object additionally has Node's four nonenumerable names. Random aliases share the refusing `randomBytes` function. Named/default identities and `getDiffieHellman` alias identity are preserved initially. Frozen records, finite constants, descriptors, and constructor behavior deliberately differ from full Node. No stream/Transform inheritance, constructor calls, copying, other algorithms/encodings, KeyObject/CryptoKey/ArrayBuffer/DataView/non-U8 Hash input, new WebCrypto implementation, FIPS, entropy policy expansion, writable default export, or `syncBuiltinESMExports` behavior is supplied. In particular the module-level `getRandomValues` remains a refusing stub; the reused `webcrypto.getRandomValues` is the already-existing native method, with its unchanged quota/receiver and selected entropy policy. Hmac repeated digest returns empty; Hash repeated digest and either update-after-digest throw.

The real registration seam is `register.cpp::evaluate_factory(cx, source, argument, result)`, with one private argument, followed by `Engine::define_builtin_module` for both specifiers. The new private argument contains the installed Buffer constructor, native constants/kernel, and existing native Crypto/SubtleCrypto objects; no public embedding API is invented. `cmake/add_builtin.cmake` appends initialization entries in declaration order and `builtins/install_builtins.cpp` calls them in that order. WebCrypto is declared before Node compatibility. Its actual `crypto.cpp::Crypto::init_class` installs the global getter and native objects; the proposed registration reads those getters before application code and checks both exact native JSClass identities. It does not call a cryptographic operation. The afterimages require `builtin_web_crypto`, entropy OFF, and the default-OFF `NODE_COMPAT_CRYPTO_HASH_HMAC` option, and link the real targets. The pure renderer makes `crypto-factory.generated.h` directly from this facade. Future integration must copy only the two declared new files into a **fresh** reviewed source root and use both afterimages; no current source or metadata was changed. A new native source count, policy/manifest selection, and artifact lineage must be reviewed rather than projected from the old 355 metadata.

The kernel uses a private one-slot foreground-finalized JSClass, not CryptoKey internals. Its reserved slot owns a native State containing EVP contexts/algorithm owners and no JS heap references. `retire` clears the slot before deletion, so explicit finalization and subsequent GC cannot double-free it. Local unique owners cover partial initialization. Live wrappers own the private handle through a WeakMap record; abandoned handles rely on actual GC finalization, which has **not** been tested. Module initialization creates no EVP state or live key; snapshotting live instances remains unsupported. The SDK147 flag and real typed-array APIs are pinned in `source-inputs.json`; this is header inspection, not frontend or runtime proof.

HMAC initialization first snapshots the exact key window into JS-allocator-owned native storage, before provider creation. Its logical bytes are cleansed on all returns. Pinned OpenSSL's default `hmac_setkey` copies the key and `hmac_free` clears that provider copy; HMAC/SHA contexts are freed by their actual OpenSSL APIs. This is not a claim that all string copies, allocator slack, stack/register spills, user buffers, provider/internal copies, or guest memory have been erased. No secure-heap/locking guarantee is made. Digest output uses a short stack buffer wiped after its 32-byte copy and then a separate bounded Buffer ownership copy.

`borrow-audit.md` follows the actual OpenSSL/SDK source paths. Copying messages is the default baseline. An explicit default-OFF `NODE_CRYPTO_AUDITED_BORROW` branch demonstrates direct borrowing of a fixed U8 window: root/materialize backing first, reject shared/resizable/detached storage, reject customized OpenSSL allocators, then re-acquire the pointer under `AutoCheckCannotGC` and synchronously call the pinned default SHA256/HMAC update. It stores no borrowed pointer and makes no JS call inside the scope. The branch is not a blanket safe-borrowing claim for arbitrary providers or callbacks. Integrated provider/allocator identity, engine imports, NoGC behavior, finalization, exact errors and allocation failure remain future gates. Native errors are currently generic typed errors from the real `api::throw_error`; exact Node error codes/stacks for provider/allocation failures are not claimed. Facade-native failures terminate access to that context; no retry-after-native-error guarantee is made.

`test-pure.mjs` uses a deliberately non-cryptographic mock kernel, host Buffer/UTF8/typed-array operations and fake 32-byte output. It checks exact windows, key snapshot/wipe timing, mutation/branding/refusal behavior, public identities, result ownership and terminal state rules. The Python owner models test only the specified lifetime protocol. These are not algorithm, JSAPI, GC, zeroization, performance, or interoperability tests. `source-checks.json` and raw evidence record every actual preparation/test attempt, including failures. `future-validation.json` provides literal vectors and the required later phases; no oracle or vector has been executed here.

All source-peer, Root, native build, packaging, import, runtime and adoption authorities in `future-authority.template.json` are NULL or false. A reviewer may issue a source-only result with schemaVersion 1, state `INDEPENDENT_NODE_CRYPTO_SHA256_HASH_HMAC_SOURCE_REVIEW_PASSED_V1`, this index's SHA256, `sourceOnly:true`, `sourceReviewPassed:true`, and all action fields false. Such a result grants no activation or workload permission.

Official reference sources are captured with URLs/hashes in `upstream-sources.json`: [crypto exports](https://raw.githubusercontent.com/nodejs/node/v22.14.0/lib/crypto.js), [Hash/Hmac](https://raw.githubusercontent.com/nodejs/node/v22.14.0/lib/internal/crypto/hash.js), [builtin ESM keys](https://raw.githubusercontent.com/nodejs/node/v22.14.0/lib/internal/bootstrap/realm.js), and [Node constants](https://raw.githubusercontent.com/nodejs/node/v22.14.0/src/node_constants.cc). These are reference code, not an executed oracle.
