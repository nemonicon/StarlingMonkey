This is a review-ready, UNCOMPILED FS v2 Source successor. The committed v1 draft is preserved through exact descriptors in `v1-reference.json`; production C++, current engines and earlier packets are unchanged. No Source peer, native build, guest, snapshot or deployment acceptance is supplied.

The new public factory installs explicit `node:fs`/`fs` and `node:fs/promises`/`fs/promises` records. Pinned Node22.14 inventories provide all106 default fs names,32 promises names and57 constant names; each namespace adds its `default` (107/33 namespace exports). Selected functions are real implementations, and remaining callables are immediate `ERR_SM_NODE_UNSUPPORTED` throwers. Default/named initial references, `fs.promises` and both constants references share identity. Stats and Dirent have real type predicates; unsupported constructors and unavailable POSIX metadata throw, rather than inventing OS values. Portable symbolic constants have explicit numeric values; platform-specific open flags/extension tags/filemap names have explicit throwing getters. No empty constants object or universal Proxy substitutes for them.

Supported ordinary operations are readFile, writeFile(w/wx), stat/lstat, access, exists, mkdir(recursive), link, unlink, rename, readdir(withFileTypes), realpath/native and readlink, with the declared sync/callback/promise variants. Paths are strings. Whole-file IO is bounded16MiB; UTF8/UTF-8/hex and fixed unshared U8/Buffer windows are supported. Input strings inherit the current Buffer1,048,576 UTF16-code-unit cap. Read bytes transfer from native JS_malloc ownership into an actual ArrayBuffer, then `Buffer.from(buffer,offset,length)` wraps that storage without another whole-file Buffer copy. Native writes stage at most64KiB across host imports. Mutations are real standard-WASI calls; no in-memory filesystem is supplied. P2 lacks POSIX chmod/umask fields, so nondefault modes/unsupported flags and unavailable Stats fields refuse explicitly. Detailed Node error text, validation/allocation ordering and arbitrary poisoned intrinsics are not parity claims.

`ReadStream` extends the actual installed classic Readable, supplied privately by registration. It holds one native owned descriptor, pushes bounded chunks only when Readable requests them, uses the real private next-tick FIFO for completion, supports inclusive start/end and closes idempotently on EOF/destroy/error/abort. It does not eagerly read a file or reopen for each chunk. `_destroy` retains a primary error if close also fails. The private JS WeakMap traces the native handle; a foreground finalizer is a Source-only backstop to explicit close. `fd` and the open event argument remain null: this profile does not expose an OS fd. autoClose/emitClose must be true, flags r, highWaterMark1..65536, total stream budget64MiB; inherited classic queue caps still apply. WriteStream/general fd/FileHandle APIs remain deferred.

Native acquisition requires actual EngineState::Initialized plus the unconditional same-TU `entropy::deployed_execution_started()` bit. It never tests entropy availability, so entropyOFF is usable. Factory/namespace installation acquires no descriptor. IO and stream construction during INIT refuse `ERR_SM_NODE_FS_INITIALIZATION`; the existing deployed transition/hook is unchanged. Standard wasi:filesystem/types+preopens@0.2.10 and cli/environment@0.2.10 are used directly, avoiding libc's snapshot-cached preopen table. Every returned preopen owned resource is dropped separately from generated list/string storage. Root must configure real standard read-only app and writable cache preopens plus initial cwd; actual capability enforcement and snapshot freshness require guest validation.

The private provider header is usable by Module/process: `read_bytes`, `stat_path`, `realpath`, `cwd`, `chdir`. cwd initially reads standard initial-cwd, then shares a provider-owned bounded logical override after successful deployed chdir. chdir performs the same genuine realpath and directory checks before committing; it does not mutate libc/global state. R owns separate Module-provider/process afterimages; they must use this API to share relative-path semantics. Fixed preopen boundary traversal can reject paths that stock Node with unrestricted OS rights accepts.

The two v1 native validation branches are repaired: integer failures in openRead(end) and readChunk(size) now return the existing pending exception before applying a separate range check. No native execution proof is inferred from those static fixes.
