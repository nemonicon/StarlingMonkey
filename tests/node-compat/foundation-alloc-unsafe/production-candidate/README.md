# Core m0.8 production candidate — uninstalled

This directory stages the coordinator-reserved `sm-node-22.14.0-m0.8` core change. It changes no repository builtins, active harness, CMake file or engine. `base/` preserves the current m0.1 sources; `source/` holds the proposed production sources and a header generated by the unchanged repository generator. The schema-valid manifest is a candidate, not evidence that an m0.8 engine exists.

The earlier [isolated wrapper experiment](../README.md), its Node/component reports and all v6/v7 records remain unchanged. Its real component used the v6 m0.1 engine and temporarily replaced a public static field within its test scope. It does not establish installed m0.8 behavior.

## Production patch contract

[core-m0.8.patch](core-m0.8.patch) changes exactly four files:

| File | Delta |
| --- | --- |
| `buffer-facade.mjs` | Capture the existing owned `Buffer.alloc` and install a normal function named `allocUnsafe`, arity 1, in its existing constructor property slot. |
| `export-manifest.node-v22.14.0.json` | Advance the core version; promote only `allocUnsafe`; document zeroing, fresh exact backing, no pool, raw size cap and fractional truncation. |
| `unsupported.mjs` | Advance only `PROFILE_VERSION`; Buffer and child-process refusals now identify the same selected core revision. |
| `factories.generated.h` | Regenerate the existing Buffer/child-process factories from those three canonical source inputs plus the unchanged child-process source. |

`buffer.cpp`, the generator, registrar, CMake, all optional facade sources/manifests/headers, all 15 Buffer exports/default relationships, constants and supported encodings remain unchanged. All 91 excluded own prototype functions and the other five static methods remain refusals. `allocUnsafeSlow`, legacy `Buffer`/`SlowBuffer` constructors and classic streams remain deferred. The shared unsupported helper gains no new error construction behavior.

The allocator accepts only primitive finite numbers in the inclusive raw range `0..16777216`. Negative fractions reject before truncation; accepted positive fractions truncate toward zero. It ignores `this` and extra arguments and remains constructible: `new`, bound construction and a different `newTarget` return the same genuine privately branded Buffer kind. It delegates to the captured existing `alloc` with the truncated integer; no new native allocation API, raw span, ownership transfer or copy is introduced.

Every successful result is zeroed and has fresh exact backing at byte offset zero, including zero-length results. This differs from Node's pooled/uninitialized storage and its larger advertised allocation limit. `Buffer.poolSize` does not select pooling. Requested sizes above the raw cap reject even when truncation would fit. No Node initial unsafe bytes are inspected by these tests.

New validation errors use captured TypeError/RangeError constructors and captured `Object.defineProperty`. `code`, `module` and `operation` are own writable/enumerable/configurable data fields, defined with null-prototype descriptors. Tests replace inherited error fields and public constructors/definition functions. Error messages remain profile text, not exact Node formatting. There is no catch/fallback around allocation. Genuine OOM behavior is unverified. Capturing `alloc` does not harden its preexisting `Number.isFinite`/`Number.isInteger` lookups; this patch makes no whole-facade primordial-immunity claim.

## Verified source/host gates

[host-results.json](host-results.json) records both actual candidate ESM and the exact generated Buffer/child-process literals evaluated as strict scripts, matching `register.cpp::evaluate_factory`'s existing `setForceStrictMode()` call. Each candidate form passes 10 differential groups against Node v22.14.0, five candidate-policy groups, export/descriptor-order checks, all 91 prototype call/new refusals, five other static call/new refusals and child-process call/new/version checks.

These are host tests using the explicitly labeled JS reference hex kernel. Allocation exercises the facade's real owned Uint8Array path. They are not compiled C++/m0.8 component evidence. The schema and all generated headers pass the unchanged generator's `--check`; `git apply --check` passes without applying the patch. Actual v6 and v7 OFF engine receipts and frozen source bytes retain the original five relevant core hashes and core m0.1. Native source hashes are not inferred from a profile version alone.

## Unapplied harness migration

[harness-m0.8.patch](harness-m0.8.patch) stages eight active-test changes in `harness/source/`, preserving their originals in `harness/base/`. No active file was modified.

| Integration point | Proposed expectation selection |
| --- | --- |
| `run.mjs`, `wasmcloud/build-http.mjs` | After checking engine bytes/full input receipts, select exact recognized core hashes and emit a build-time `node-compat:core-expectations` virtual module. Carry the same policy in reports/HTTP audit. |
| `fixtures/component.mjs` | Use the selected core error version/static refusal inventory; preserve the 91-method gate; check supported zeroed allocation only for the exact m0.8 policy. |
| `optimization/intrinsics-checks.mjs` | Consume the same mandatory build-time core version. |
| `wasmcloud/run-host.mjs`, `test-wasmtime-http.mjs` | Validate the audited policy and check native report/stub error versions against it. |
| `optimized-profile-tests.mjs` | This source-only test imports `PROFILE_VERSION` from the same source tree as its facade; it does not claim an engine receipt. |

The new host-only `core-expectations.mjs` delegates module admission to the existing `selectedManifestsForEngine`. It recognizes the exact current v6/v7 m0.1 inputs and these proposed m0.8 inputs. It rejects unknown versions, missing/mismatched compiled input hashes, duplicate inputs, incoherent optional selections and malformed policy payloads. A truthy function or a successful catch/probe never selects support. The virtual module is test metadata, not a public guest feature toggle.

[harness-host-results.json](harness-host-results.json) records 46 host cases, including 39 rejections, eight syntax checks and patch applicability. Actual archived m0.1 receipts pass selection; m0.8 selection uses explicitly synthetic receipt data and staged bytes, never a claimed build. The unchanged ordinary facade regression body also passes against both preserved source versions with only host import URLs relocated.

Historical reports and the original m0.1-only isolated allocator runner intentionally remain m0.1-only. Replaying an old component report does not use new expectations. Older m0.1 sources with different hashes require their preserved runner/source bundle; the new selector does not silently admit every historical use of the m0.1 version label.
