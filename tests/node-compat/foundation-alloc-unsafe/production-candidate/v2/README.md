# Uninstalled core m0.8 candidate, revision 2

This revision keeps the coordinator-reserved `sm-node-22.14.0-m0.8` version and preserves the complete v1 candidate/index, original m0.1 controls and all historical reports. No production file, active harness or engine is changed. Relative to v1, only `unsupported.mjs` and the regenerated core header change; the bounded zeroed allocUnsafe facade, manifest and native buffer.cpp are identical.

The shared helper now captures the installation-time Error constructor and Object.defineProperty. It constructs the same message and defines `code`, `module`, `operation` and `profile` as own writable/enumerable/configurable data properties, using null-prototype descriptor literals. Replaced global constructors/definition functions and inherited error-field hooks cannot substitute for those fields. It introduces no Proxy, getter, thenable, new export or host capability.

This deliberately changes behavior under application monkey-patching: later replacement of global Error or inherited field setters no longer controls profile refusal errors. Ordinary messages, Error kind, field values/order/attributes, finite exports and call/new refusal semantics are preserved. Captures occur when the existing registrar eagerly evaluates both private factories during builtin installation. The same source ESM helper captures at module evaluation; it is not a newly exposed native module.

[core-m0.8.patch](core-m0.8.patch) remains a full four-file patch against the original m0.1 sources. [harness-m0.8.patch](harness-m0.8.patch) carries the same eight-file receipt-selected migration, with exact v2 helper/header hashes. An old unbuilt m0.8 proposal with different source bytes is rejected; the version string alone is not evidence. Actual v6/v7 m0.1 engine/source controls still pass. There has never been a released/accepted native m0.8 engine to migrate.

[host-results.json](host-results.json) passes actual ESM and exact generated strict-factory forms: 10 allocation differential groups and five profile groups each, 15 Buffer exports/default graph/property order, all 91 prototype refusals, five remaining static refusals and finite child-process call/new/version checks. [harness-host-results.json](harness-host-results.json) passes 46 receipt/policy cases, including 39 rejections and eight syntax checks. Generator `--check` and both `git apply --check` operations pass without application.

[stub-hardening-results.json](stub-hardening-results.json) separately records **240 pure-JS call/new refusals per form**, including all 91 Buffer prototype functions and the finite child-process exports/prototype methods. During a synchronous window it installs throwing inherited getter/setters for all four error fields and replaces global Error/Object.defineProperty. Each operation retains its four own data fields; all poison hook counters stay zero. Every hook restores in finally.

The poison window runs **only our pure-JS refusal functions**. Factory/web constructor creation, inventory, Node allocation oracles and assertions run outside it. No actual Node child_process operation is used as a stub oracle, and no native Node codec/error construction oracle runs under inherited field poisoning. The earlier stopped native combination is not repeated. The reference hex kernel remains an explicitly labeled host test double; no m0.8 component or native engine is exercised.

This is narrow hardening of the shared refusal helper and the already captured allocUnsafe validation. Other existing facade validation paths still have their earlier primordial assumptions; this patch does not claim whole-Buffer immunity to arbitrary application mutations. Property allocation/Error construction can still fail under genuine memory exhaustion, which is untested; such failures propagate without a catch/fallback or a fabricated unsupported/OOM error.

After coordinator review, apply source and harness patches coherently, build a fresh hash-receipted engine and run installed native module/alias/default/static-CJS, top-level failure, snapshot/reuse, zero-import and joint-host gates. Those remain pending. Native Blob changes, classic streams, decoder/abort/scheduler expansion and performance claims do not follow from this core revision.
