# Blob v2: contract correction and syntax checkpoint

This separate candidate preserves the reviewed v1 sources/receipt/index verbatim. It fixes a decoder contract issue caught before any native execution: UTF16 decode requires at least two writable units. V2 allocates `max(maximum,2)`, passes that complete checked capacity and compares the declared `jsencoding::INPUT_EMPTY` constant. A later ordinary suite must include a one-byte, one-code-unit nonempty Blob text case as a regression. No old native Blob candidate was run.

[contract-proof.json](contract-proof.json) pins the generated encoding header, local encoding_c0.9.8 implementation and exact SpiderMonkey revision `9dab3d6f643e926a340c391ea30968e940390dec`. Status0 means INPUT_EMPTY; the FFI overwrites src_len with bytes consumed and dst_len with UTF16 units written. With last=true, InputEmpty ends the decoder stream. The worst-case capacity function returns SIZE_MAX on overflow; checked multiplication rejects that case. Zero-length Blob text returns before FFI.

The same proof traces the allocator family, rather than assuming compatible destruction: `JS_malloc` calls JSContext's MallocProvider `maybe_pod_malloc<uint8_t>`, selecting `js::MallocArena` and `js_pod_arena_malloc`. SystemAllocPolicy's AllocPolicyBase selects that same arena for allocation and later realloc, and frees via js_free. Thus the native vector's documented replaceRawBuffer policy is met for JS_malloc bytes. JS_string_malloc deliberately selects StringBufferArena for the separate adopting string API. The JSContext allocation-counter update differs from SystemAllocPolicy; external-memory pressure/accounting is not proven complete by this ownership proof.

[sdk-syntax-results.json](sdk-syntax-results.json) records **two successful actual SDK30/SM147 Release syntax checks**, Blob and File, using their exact v7 compilation entries. The candidate headers resolve through an isolated quote-include overlay; remaining web/include headers use the frozen v7 source where available. Compiler/wrapper hashes, compiler version, compilation-database hash, full commands and actual included-header hashes are retained. No object, linked engine, component or native runtime test was produced.

The [four-file v2 patch](blob-owned-copy-v2.patch) remains unapplied. The v1 ownership/finalizer design and its explicit backing, WebIDL/options, Rust-allocation and stream limitations still apply.
