This is a source implementation for a fresh consumer355 release and follow-on
family. It is held for independent review. Nothing in this candidate authorizes
publication, a preflight, a component, a host run, a native build, or timing.

`publish.py` is a concrete, unexecuted source-only publisher. It accepts an exact
candidate index hash, a new Root source-review document, and external reviewed
four-variant native pins/review arguments. It authenticates the complete source
index and original preparation inputs before copying, checks them again before
publication, and reserves the new sibling `release-gates-activated-v1`
exclusively. It preserves incomplete exclusive output as failure evidence. The
checked-in source-review and runtime-action templates retain NULL authority.

The future generated family has two separate contexts: native bootstrap stays at
the actual configured `/private/tmp/starling-node-compat/consumers-source-v2`
checkout; component tooling and inherited test bodies use the new family’s
`snapshot` directory. The frozen native source remains
`/tmp/starling-node-compat/production-consumers-v1/native-freeze/source`.
`source-inputs.preparation.json` and the candidate `input-freeze.json` describe
original absolute preparation paths. No nested old manifest is rebased onto the
snapshot or reopened as an old preflight.
Those original preparation bytes remain explicit integrity inputs after source
publication. Moving them later requires a fresh archive-aware source revision;
this candidate does not silently redirect original paths to archive copies.

The bridge authenticates its config/input primitives, explicit generated-index
hash, all indexed files, complete snapshot membership, live repository adapter,
seven standard WASI declarations, package versions, five resolver endpoints,
package provenance, two complete tool trees and 22 links before owner imports.
The physical selected graph is separately listed in `selected-closure.json`.
Its finite regex scan applies to these exact pinned sources; it is not a general
JavaScript parser. The complete snapshot inventory also seals dynamic fixture,
corpus, oracle, schema, manifest, ABI/clock and policy data. The 767 native build
tool rows are preserved as data and do not stand in for component-tool closure.

`validationPreflight` uses the genuine indexed `consumersBootstrapPreflight`,
then the existing named `metadata-admission.admit` build gate. It captures the
actual full355 metadata, selected manifests and validated m0.11 core expectations
in a private frame. Later synchronous host helpers accept that exact frame and
frozen source root. The ordinary355 operational selector is unchanged and stays
closed. The registrar guard authenticates the unchanged 306-source Node oracle
documents and the complete 306 → corrected342 → 350 → 355 source-policy chain.
It does not give old metadata a new identity or validate a subset under an old
helper. Strict/protected tags and all355 native source bytes stay exact.

The eight fresh entropy-OFF stages are core, allocator, stream/web, the six-module
optional batch, and strict sync/runtime/late/callbacks. Optional modules retain
path, events, string-decoder, assert, querystring and util. The safe Path oracle
copies keep their original bytes and write only to a fresh output. Separate
scopes retain allocator-GC, focused OFF/RuntimeOnly/GC and the getter
counterexample. “Strict-runtime” is an OFF test-stage name. RuntimeOnly is used
only by the explicitly separate focused-runtime scope.

Afterimages change host bindings, obsolete admission/report labels, the
registrar ancestry guard, and the generic harness’s duplicate source-directory
report write. Guest/corpus/oracle bodies remain inherited. Each host edit has an
exact preimage and an ordered reversal proof. The separate m0.1 allocator and
m0.8 delegated numeric-hook controls are retained alongside the older optional
module-OFF controls. Those exact older metadata/source tuples may use the
unchanged ordinary selector/core checker; an unknown historical tuple refuses.
They are historical control origins, never new355 runtime passes.

All four independently reviewed native tuples are bound externally. The checked
in pin templates in the native producer stay unchanged. Only normal-off,
normal-runtime and gc-off are selected by these release/follow-on scopes; the
disabled consumer tuple remains part of the reviewed four-variant authority.
The existing 207 returned-string normal/GC/disabled consumer record is a bounded
prerequisite, pinned by `36964b…`; it supplies no new release pass or RuntimeOnly
consumer result. Metadata backend proof remains false/null/null and operational
consumer admission stays closed.

The supported future caller is `entry.mjs`. It uses only Node primitives to
authenticate the externally supplied generated-index hash and every indexed file
before importing any owned helper or driver. It dispatches an explicitly chosen
read-only `preflight` mode or a separately authorized `run` mode. Direct legacy
entry points are not the action interface.

After a generated-family review, a new Root runtime-action document must name
the exact generated index, the bounded consumer prerequisite, each approved
scope, fresh output and deadline. `run-gates.mjs` then owns one process group,
retains separate stdout/stderr and raw terminal status before asserting success,
cleans up only that owned group, and rechecks the source after completion. Its
2-hour ceiling is a bound, not an assertion that all future inputs fit it.
The output namespace is
`/tmp/starling-node-compat/production-consumers355-release-gates-v1/`; the Root
action creates that parent directory before dispatch. Resume and prior-pass
adoption refuse. The source publisher and fresh scope require 2GiB free before
starting; serial stages and source copies retain the 800MiB stop floor.

Every OFF/GC final component must retain no emitted imports; RuntimeOnly focused
components may emit only `wasi:random/random@0.2.10`. Selected interfaces and
component audits retain their existing checks. No private or custom host service
is added. Actual component counts must come from future reports. HTTP source and
both-host publishing are intentionally deferred to a new sibling.

Known evidence limits remain: the getter report keeps Node compatibility false;
GC fixtures retain combined owners and cannot isolate temporary roots; a generic
Wasmtime trap does not establish a unique error origin; some inherited harness
reports store stdout hashes instead of full main raw stdout. This source cut
does not manufacture missing raw records. There is no reset/ALS/request reuse,
full Node, full consumer, crypto ownership, backend-version, performance or memory
claim. No DEBUG/OOM/fault/raw-memory/reset probe is introduced.

Only owned preparation, source/byte checks, pure contract checks and parse-only
syntax checks have run. The first two pure derivation attempts made incorrect
assumptions about a direct late-runner selector and a mixed-case report label;
one preparation edit then had a syntax typo. Their source/partial bytes and
failure notes remain under `preparation-history`. The resulting candidate has
not been published or exercised by a guest.
