The first extra encoding comparison stopped when the unchanged canonical host factory threw ERR_UNKNOWN_ENCODING for an object-mode write with an arbitrary encoding string. Node22 ignores encoding validation for object mode; this is a real old-source counterexample, not a candidate failure. The comparison harness now records that thrown result and destroys/closes the ordinary stream, so a fresh run can compare all remaining cases. No live source, scheduler, guest or native engine was changed.
