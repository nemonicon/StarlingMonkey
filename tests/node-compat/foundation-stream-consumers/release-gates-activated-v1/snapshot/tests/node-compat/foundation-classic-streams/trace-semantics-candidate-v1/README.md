This is a **source-only, unapplied** Node22 writable-stream semantic fix proposal. Live source342, policies/metadata, four production pins, sealed workloads and the approved measurement producer remain unchanged. Proposed core/receipt/header afterimages have not been compiled or executed in StarlingMonkey. There is no benchmark or native-performance claim.

Two source differences explain the observed workload gaps:

| Difference | Canonical readable-stream4.7-derived path | Pinned Node22.14.0 path | Proposed change |
| --- | --- | --- | --- |
| Synchronous write return/backpressure | Computes return/needDrain before invoking `_write`, while the just-added chunk is still counted. | Computes after `_write`; a synchronous completion may already have removed the chunk. An empty queue also returns true at HWM0. | Move the return/needDrain calculation after dispatch and preserve errored/destroyed refusal. |
| Object-mode encoding | Defaults/validates encoding before the object-mode branch. | Defaults/validates only byte-mode encoding; object-mode sees the caller's encoding, including undefined or null. Public `write` handles its callback overload. | Move default/validation into the byte branch and match public overload normalization. |

These are five reversible text edits in the transformed writable module. Raw24 vendor files, queue limits, Buffer/view checks, private scheduler, callback implementation and all other stream modules are unchanged. [Node22 writable source](https://github.com/nodejs/node/blob/v22.14.0/lib/internal/streams/writable.js) is pinned byte-for-byte in `primary-source-pins.json`, retaining its MIT notice. Existing readable-stream/Node notices are copied here.

The event-order mismatch is a consequence of backpressure in the tested topologies, not proof that the scheduler or `_final` is wrong. Existing `Readable.pipe` pauses after a false `dest.write` result and awaits drain. An unnecessary false result changes that flow and its event interleaving. The **return-only** ablation matches all eight minimal public traces, including the observed end-before-finish ordering. The first experiment also ported Node's different `afterWrite` ending scheduling; that experiment passed, but was unnecessary here. It is retained in history/ablations and excluded from the final five-edit proposal. No universal ordering rule for every Duplex/Transform topology is asserted.
