# Versioned manifest validation

The existing [export manifest](../../builtins/node-compat/export-manifest.node-v22.14.0.json)
is validated against [manifest.schema.json](../../builtins/node-compat/manifest.schema.json)
before the deterministic factory generator accepts it. Normal CMake builds still
consume the checked-in header and require no Node/npm invocation.

The dependency-free [validator](../../builtins/node-compat/validate-manifest.mjs)
implements the exact JSON Schema vocabulary used here, including local `$ref`,
object/array/string/numeric constraints, required fields, closed properties,
patterns, enum/const and unique string arrays. Unknown schema keywords and
external references fail. This is a deliberately restricted validator, not a
general JSON Schema implementation. The schema is versioned and future schema
features require explicit validator/test changes.

Schema checks cover the pinned Node release, profile identity, support-status
vocabulary, finite unique export names, aliases, typed limits/numeric constants,
and fully versioned standard WASI 0.2.10 interface names. Semantic checks also
require an explicit default export, reject `then` bindings, prevent alias
collisions, and require import-only/numeric members to be declared exports.
The selected manifest continues to require **zero** host interfaces. A schema
accepting a future standard interface does not grant it to an application or
select a world automatically.

The [execution record](../../tests/node-compat/manifest-results.json) identifies
the tested source/header hashes. The regression imports the two actual pinned
Node namespaces and compares their exact named/default inventories, checks
constant types, rejects 19 malformed manifests and an unsupported schema
keyword, and accepts a versioned standard-interface declaration. The factory
generator's `--check` still passes with unchanged generated bytes. This adds no
runtime API or host service.

```sh
/path/to/node-v22.14.0 tests/node-compat/manifest-test.mjs
/path/to/node-v22.14.0 builtins/node-compat/generate-factories.mjs --check
```

A manifest entry does not install a module by itself. New exports/modules still
need real factory bindings, existing native registration/CMake integration,
Node differential cases, component tests and versioned compatibility decisions.
