# Native ALS v2: Source ready for frontend review

This is a separate, uncompiled native implementation candidate. Committed v1 is unchanged. No compiler, monitor, producer, helper, engine, component, guest, GC-pressure, OOM or reset workload has run for v2. Source review, SDK execution and native/runtime admission remain separate. This family does not claim that Next runs in Wasm.

The14 existing-file afterimages are now derived by43 exact forward/inverse edits from the actual retained9aec configured source. Four divergent v1 anchors were adapted: the traced retiring/running task owners and the newer owned timer constructor/registration. Crypto/zlib registration, timer retirement/drop/allocation ordering and the existing strict event/tick policy remain intact. `localized-edits.json` is the composer input; **do not overlay old v13 whole files onto9aec**. Namespace/INIT, Module, FS, process, util/Concat and streaming-zlib successors are separate Root composition inputs.

The implementation uses native mutable cells, rooted current/owner/server resources, actual SM147 creation metadata and the real legacy `JS::JobQueue`. It selects the legacy preference before self-hosted initialization, installs metadata builders in both actual shared-compartment realms, traces queued jobs/resources and enters the job's actual realm. It validates the pinned11-slot reaction layout and uses real target Promise metadata or registration data. Unknown jobs/foreign compartments refuse. Custom species returning a non-Promise are explicitly unsupported: borrowing the resolver's current request owner is not proved correct by old single-owner experiments. Real-Promise species retain creation metadata support. Ordinary tasks capture before host subscription; repeated tasks keep their cell; cancellation and tick callbacks enter their registered resource. No Promise monkeypatch or deployed JavaScript stack carries context.

V2 adds a persistent neutral server owner and private `run_neutral_server`/`run_neutral_server_native` alongside `run_fresh_request`/`run_fresh_request_native`. Both JSNative signatures are `(callback, receiver, ...args)`. They are proposed private HTTP-factory bindings, **not public async_hooks exports and not yet wired into any HTTP guest**. Prepare the app once under neutral server ownership; keep readiness/cache infrastructure there. After readiness, enter a fresh request resource before constructing the request body/response streams. Async descendants retain that owner's identity after the initial native call returns. Merely wrapping the eventual handler is too late for earlier stream construction.

Material fixes include validating delayed fetch response context before clearing its pending handle, enforcing job/resource compartment equality, rejecting debugger coexistence at CMake selection, and checking queue/server quiescence through existing pre-snapshot/reset hooks. Quiescence checks never drain or repair state. They reject pending/draining/stopped jobs, a rejected off-thread submission, or entry from a request/captured child. This is not a reset-safety or request-expiry proof. Request cancellation/host-handle ownership/teardown still needs the real HTTP factory's lifecycle work and ordinary runtime evidence.

The retained9aec embedding's ordinary dispatch paths call `run_event_loop`; they do not call `Engine::reset`. Repository runtime/crates likewise contain no reset caller. V2 does not add a reset or GC call to warm HTTP entry. Queue/server quiescence is only a necessary boundary check; it does not validate deployed re-snapshotting, FS streams, native EVP lifetime or arbitrary retained-handle reset.

The allocation-metadata callback/table uses the explicitly fatal experimental component-allocation policy. No recoverable-OOM promise or fault test is made. SM off-thread/delayed dispatch is outside this first profile: submissions are refused one-way without JS/GC and a sticky failure is observed at checkpoints and quiescent boundaries. Existing finalizer ordering/strict exception handling remains; FinalizationRegistry registration-context propagation is outside this ALS contract. Native tracing, private ABI, snapshot/resumption, cancellation, queue limits and linked behavior are still unproved by host models.

Old83-field frames, bootstraps and hardcoded manifest selectors must reject this generation. Root owns that producer; its actual Source/WORK/artifact/metadata slots remain unissued here.
