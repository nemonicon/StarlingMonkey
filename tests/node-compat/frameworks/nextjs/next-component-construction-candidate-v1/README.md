# Dormant raw Next component construction

This small caller invokes the genuine private `componentize` API. It supports
the held raw `dependencies` and `real-next` entries with the same WIT directory,
selected13 standard interfaces, and adapter `d30ade5b…`. It retains stdio,
random, clocks and HTTP, disables only fetch-event, uses `enableAot:false` and
an empty Wizer application environment, and keeps all debug options off.
No bundler, old clock loader, host Node adapter or global pin is substituted.

Source preparation has not invoked ComponentizeJS, Wizer, the engine or any
guest. Root must separately issue the complete authority described by
`root-authority.template.json`, bound to this final index and actual new engine,
whole native metadata, build evidence and Source evidence descriptors. The
actual metadata is retained verbatim and Root's exact fixed fields are checked;
no old83 frame/schema/count projection is performed. These descriptor guards
consume Root's reviewed build selection; they do not independently re-prove
the native build or recursively replay historical protection trees.

The future command is:

```sh
/Applications/Xcode.app/Contents/Developer/Library/Frameworks/Python3.framework/Versions/3.9/bin/python3.9 -B -I \
  tests/node-compat/frameworks/nextjs/next-component-construction-candidate-v1/run.py \
  --authority /absolute/issued-root.json --sha256 ROOT_AUTHORITY_SHA256
```

The wrapper runs one pinned Node22 caller under the original0af owned monitor
for1800s, then independent `wasm-tools validate` and `component wit` commands
for120s each. Every actual emitted import must be a subset of selected13 and
exactly0.2.10, with only `wasi:http/incoming-handler@0.2.10` exported. Unused
interfaces may prune. Mixed versions, Preview1, custom imports or extra
capabilities refuse after original bytes have been captured. There is no
version rewrite, post-return repair or world widening.

The Node caller authenticates this Source family, the unchanged entry/WIT
family, complete existing private package4889 regular files/21 aliases, engine,
metadata and all supplied evidence before its first custom import and again
in finally. It reuses the pinned existing package inventory as DATA, without
copying its inherited trees. Outer validation checks all direct Source/tool/
engine/evidence descriptors before/final and around each command; package
whole-tree checks specifically bracket the actual Node API call.

`capture.mjs` first saves the complete actual returned Uint8Array, then the
typed own-property graph (including `debug:undefined`, descriptors and extras),
then full returned import DATA before semantic admission. Malformed returns
retain their available byte/shape records and refuse. If the real API throws
before returning, no component bytes are inferred. Existing package cleanup
can make its internal temporary outputs unavailable. Debug stays off because
the installed package has unsafe uninitialized debug-output branches.

The package's genuine API itself performs Wizer INIT and its `initWasm`
check-init call; a later Root INIT grant covers those mechanisms. It invokes
no ordinary component export and mounts no application. Native bootstrap,
`require('next')`, neutral readiness and `/app` filesystem work stay in the
held guest's deployed request path. Dependencies and real-next require separate
fresh output roots/authorities. Any result file remains UNREVIEWED; acceptance
also requires the actual clean terminal and final guards. A final guard failure
can leave captured bytes or a Node UNREVIEWED result while the process fails.

On actual success, `result.json` exposes `entryMode` and `artifacts.component`,
`componentAudit`, `inputEntry`, `inputSourceIndex`, `engine`, `nativeMetadata`,
`engineBuildEvidence`, `adapter`, `returnedImports` and `returnedOwnShape`.
`component-audit.json` carries the actual emitted/unused interface lists,
export list and genuine original0af validate/WIT terminal descriptors. This is
construction DATA, not HTTP, full Next, production or deployed re-snapshot
acceptance. Deployment is a separate Root-owned harness.

The installed API exposes no semver option: Jco's third `false` argument is
ignored by its two-argument JS wrapper. Installed vendor binary paths identify
wit-component0.259.0. The version-tagged Rust wrapper uses
`ComponentEncoder::default()` and encode with validation; that encoder defaults
semver merging on. Primary Source links and the correlation limits are in
`plan.json`. Actual final validate/WIT audits remain mandatory.
