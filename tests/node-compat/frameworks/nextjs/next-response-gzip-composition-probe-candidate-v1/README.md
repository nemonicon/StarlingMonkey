# Dormant gzip response-composition probe

Source only: no JavaScript evaluation, Node grammar/VM invocation, HTTP, component construction, engine or guest run has occurred. This family has no index or Root authority yet. Existing native, stock, cache, browser and failed prefix-trial results remain unchanged.

The new guest keeps the exact V5 entry prefix, six facade installations, `createWasiHttpHandler`, ownership/error cleanup and neutral readiness. The only added static import is the existing `node:zlib` builtin. Its deployed `prepareServer()` calls the actual exported `createServerHandler(() => nodeHandler)` API, then hands the returned Web handler to that unchanged adapter. No new embedding API, WASI interface, server service or app/fixture mount is introduced. INIT executes pure installations/declarations only; bootstrap and compressor allocation are deployed-only.

`handler.mjs` manually mirrors the selected Next compression handoff: gzip `data` → `res.write`; false → gzip pause; response `drain` → resume; gzip readable `end` → original response `end`. It uses the real selected classic stream and native streaming-zlib implementations through public `node:zlib`. One small ASCII response and one deterministic 2-MiB xorshift fixture are served at the two exact GET paths in the plan. If a response closes before its finish event, the probe records the failure and publicly destroys its own compressor, including a paused compressor that can no longer receive response drain. Normal completion is unchanged. It is a generated-body composition test: it does not select an internal Next redirect fetch, native append, clone or request-body branch, and does not load Next.

The standard-stdout marker `NEXT_GZIP_COMPOSITION_V1` records bounded per-request public events/counters. These are sequence numbers within that request, not identities. No clock, entropy, private state, Store ID, finish/drop count or resource counter is read. The future standard Wasmtime host argv must explicitly include `--no-logging-prefix`; marker parsing does not rely on reuse128 implicitly removing prefixes. Public logging adds a deliberate perturbation; a pass cannot establish the cause or reliability of the earlier action/browser failure.

`node-reference.mjs` is independently written and uses real Node22 built-in `Readable`, `createGzip` and `pipeline`. It imports no candidate helper/provider. It generates plaintext and compressed files plus raw event/error records, without an HTTP server. Its raw reference does not claim to mirror guest HTTP hosting. The shared stdlib DATA verifier compares decoded fixture bytes and valid single-member gzip/CRC/ISIZE, not compressed-byte identity, chunk partition or event timing.

`capture-wire.mjs` is dormant Source for two explicit loopback GETs, each on its own ordinary `Connection: close` socket. The consumer waits 250 ms before reading and 10 ms between reads. A 20-second total deadline and 4-MiB response cap bound each capture. Raw request, response wire, partial data and original errors are published before semantics. Socket EOF is retained as its own fact; the verifier separately parses complete Content-Length/chunked HTTP framing and one complete gzip member. Raw HTTP field controls are rejected before trimming only SP/HTAB. File sync and close are attempted independently and both failures are retained. No browser or navigation is involved.

`verify-data.py` reads only explicit retained files. It requires two ordered cases, exact byte fixtures, no extra HTTP data, no concatenated/trailing gzip bytes, CRC/ISIZE and public normal completion. Actual large guest **and** Node compressed output must exceed 64 KiB; Source does not establish incompressibility. Backpressure coverage additionally requires observed public response write(false), drain, pause and resume counts. Wire verification can pass while that coverage stays false. There is no retry or inferred branch when it remains unobserved. Public `gzip-end → res.end call → response-finish → response-close` is checked; no record asserts a private WASI finish call occurred once. Wire completion and public event order are observable checks only.
