# Standard handler return observer prototype v2

`observer.wat` is concrete hand Component Model source, not a proposal-only stub. It imports and exports the same standard `wasi:http/incoming-handler@0.2.10`, imports the common HTTP resource types, forwards owned request/outparam exactly once through canonical lowering, and reaches an ordinary fixed stdout site only after that synchronous imported call returns. No public metadata/correlation, headers, body read, outparam set, request replay, new host interface or manual post-return is selected. No imported function is called during instantiation.

Compose the unchanged direct-WASI probe component and this observer as SIBLINGS inside an envelope; outer describes call order, never lexical ancestry. C's genuine WAC CLI mechanism is `wac plug --plug INNER.wasm OBSERVER.wasm -o ENVELOPE.wasm`; Root owns the selected tool build and every invocation. The first intended normal workload is one GET `/none` to the existing non-Next probe component in manifest.firstProof. This family contains no authority or launch controller. The new observer/envelope/validation/runtime fields remain NULL.

The WAT imports resource types with `sub resource` and uses equality aliases into the standard handler, streams and stdout signatures. The core's i32 own-handle representation is strictly local canonical ABI: its sole two-argument inner import is `canon lower` of the typed standard handler. No raw table index crosses components manually; there is no resource.rep/new or opaque custom interface. After forwarding begins neither request nor outparam is reused, dropped or retried, including trap paths. Stdout's separate owned output-stream is acquired afterward, borrowed by the real standard blocking-write-and-flush, then dropped; a returned last-operation-failed error handle is dropped before a trap.

The fixed64KiB memory holds the two ASCII records and a wasm32 return area. Lowered blocking-write-and-flush has four i32 arguments: stream, byte pointer, byte length, trailing result pointer. Canonical variant layout places result tag at512, stream-error tag at516, and last-operation-failed own error at520. These are implementation assumptions checked against the retained ABI algorithms and actual selected standard WIT, and MUST pass Root's real parse/type/validation before execution. No allocator or binding generator is needed.

Each observer instance emits at most256 complete94-byte `inner-handler-import-returned` lines, then one77-byte `record-limit` line, then none. The cap advances before the write; stdout failure/drop can trap, may publish partial bytes and is not retried or called harmless. No raw IDs/counts are emitted. The record budget is local state, not physical identity or cross-instance evidence. Complete capture, exact line parsing and a normal owner are future DATA prerequisites. Protocol fields/limits are in protocol.json.

Actual generated synchronous adapters must preserve the unchanged inner's explicit post-return option and complete it before the lowered import returns.
