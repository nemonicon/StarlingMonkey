# Future standard-handler return observation

This is feasible at the Component Model/Wasmtime Source level, with implementation held pending an exact composition encoder and resource-type validation. A small observer could export `wasi:http/incoming-handler@0.2.10`, snapshot bounded public metadata, synchronously forward the same owned request/outparam through an imported **standard** incoming-handler, then emit a bounded standard-stdout record after that imported call returns. That could witness a later boundary than the current native-success-return-site. Nothing here is implemented, compiled, composed or executed; the completed pair and its failed legacy gate remain unchanged.

The component topology matters. The observer and unchanged Starling component must be **siblings inside a composite envelope**. “Outer” describes the call graph, not lexical instance ancestry. Pinned Wasmtime42's fused-adapter compiler unconditionally traps calls between identical or ancestor/descendant component instances (`fact/trampoline.rs`117–129). The envelope should instantiate Starling, instantiate the observer with Starling's incoming-handler export as its incoming-handler import, then expose only the observer's incoming-handler export. No custom host service, core ABI export, external handler import or host modification is proposed. [Wasmtime42 primary Source](https://github.com/bytecodealliance/wasmtime/blob/v42.0.1/crates/environ/src/fact/trampoline.rs#L117-L129).

The intended synchronous boundary is concrete: the same compiler emits the inner core call at834, result translation at853, optional callee post-return at858–863, resource-call exit at869–872 and final adapter completion at890. Ordinary observer code after the lowered import returns is beyond those steps **if the future generated adapter actually takes this synchronous path and retains the selected inner post-return option**. The pinned Canonical ABI calls synchronous post-return before returning from `canon_lift`; lowered imports are forbidden during post-return. Therefore stdout belongs after the import in ordinary observer code, never inside inner or observer post-return. No explicit manual second `post_call` is appropriate. The current inner component's generated canonical options have not been inspected in this audit; that remains an artifact check, not a Source assumption. [Canonical ABI pinned primary](https://github.com/WebAssembly/component-model/blob/d230073ce81c6634f175b4d0c5ad900b5253f1f4/design/mvp/CanonicalABI.md#canon-lift), [Wasmtime42 fused adapter](https://github.com/bytecodealliance/wasmtime/blob/v42.0.1/crates/environ/src/fact/trampoline.rs#L831-L890).

The wiring must share the **same imported** `wasi:http/types@0.2.10` resource types, not independently define lookalike types or pass raw numeric handles. The standard handler takes owned `incoming-request` and `response-outparam`; canonical lifting removes owned handles from the sender table, validates exact runtime resource type and rejects outstanding lends, while lowering allocates receiver-local handles. The observer may borrow the incoming request for method/path/header inspection before forwarding. Its temporary `headers` child must be dropped before ownership transfer; after transfer it must neither reuse nor re-drop either owned argument, including uncertain/trapping transfer paths. It must not consume the body, clone/rebuild the request, replace the outparam, buffer/replay a body or interpose on response completion. WIT `types`249–271/391–414 and `incoming-handler`636–651 define these actual APIs; Canonical ABI2430–2461/2873–2884 defines ownership translation. `response-outparam.set` can precede further execution, so response delivery alone is not this return witness.

Snapshot only fixed method/path enums and the existing public correlation field. Standard `fields.get(name)`188–189 returns all values for that name; it does not promise a fixed allocation bound. A future implementation must bound accepted value count/length, copy only validated 64-lowercase-hex into local fixed state, preserve missing/invalid/duplicate/unknown categories, release temporary results/children before forwarding, and document the binding's allocation behavior. It must never retain resource handles or arbitrary header text for later logging. No query/body replay, new request headers, clock, entropy, numeric identity or global current-request slot is needed. Per-invocation local state survives the synchronous call. Shared public values across GET/POST/instances still require the existing conservative cardinality rules; they are not physical request/Store IDs.

A future marker would need a new name, fixed ASCII fields, bounded line/record counts, complete raw capture and explicit I/O failure behavior. Trap or absent output stays unobserved; do not catch/retry/reconstruct uncertain ownership or treat stdout failure as harmless. A post-import marker can itself block/trap, alter timing and stack depth, add resource-table translations/copies, and change component lifetime/reuse costs.

A positive marker could prove only that this observer's synchronous inner canonical call, including its configured post-return, completed before that ordinary output site. The observer's own C return/canonical post-return, final host task completion, transport EOF, process quiescence, private identity, cause, unchanged scheduling or full Next acceptance would remain unproved.
