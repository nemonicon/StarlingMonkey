## Raw capture and precise observations

The TCP decoder descends from the exact authorized Node reference helper. The
new client parameterizes only the leased port/output/milestone provider and
durably appends received bytes before frame inspection. It retains full raw
HTTP, decoded body bytes, client socket events/errors and actual close method.
End/destroySoon are normal APIs, not packet-level FIN/RST proof. Prefix return
followed by `input-read-invocation-attempt` is a call-site barrier, not proof the
host entered or suspended its read. Client close or response-close alone is
never a guest write error. Unknown payloads and failures remain typed evidence.

All raw response files, stderr, structured events and classifications are saved
before deciding another request is safe. The parser checks exact guest schema,
origin and known phase inventory. A complete known normal handler path requires
entry, handler-finally, matched write-attempt/returned counts, outgoing finish
and adapter-finally, with no adapter/write/dispose failure and no client capture
failure. Healthy controls also require actual full content and correct factory
tag/ordinal. Missing milestones, changed factory/ordinal or unknown completion
stop the cohort and require owned-server discard.

In particular, `adapter-finally-returned` on a rethrow path **does not** prove
export completion or authorize another HTTP request. Any `adapter-failed` makes
the invocation outcome unknown, even if reader-cancel and finally were logged.
No new Wasmtime per-request completion/discard marker is invented. Inspection is
attempted only after the exact known normal path. Otherwise after-return cleanup
is inconclusive, and the next independent cohort starts only after the previous
host's actual terminal outcome. No same-instance reentry is forced.

`last-operation-failed` and `closed` are retained as WASI variants, separately
from Node's ECONNRESET/ERR_STREAM_DESTROYED reference categories. Closed under a
short Content-Length is not successful HTTP completion or a proven peer reset.
All eight bounded output writes being accepted gives inconclusive disconnect
propagation; an actual later known WASI write error plus real producer/reader
cancel observations is needed for within-export output-path coverage. No
Node/WASI error-enum equality is required or fabricated. Real error diagnostics
remain the held adapter's toDebugString/drop behavior; typed httpErrorCode
extraction and trailer completion are still absent.

## Result fields are distinct

- `observationsValid`: bounded collection, source preservation and clean owned
  server shutdown/integrity conditions. It is not a disconnect PASS.
- `functionChecksPassed`: both cohorts' full healthy upload/output controls.
- `withinExportIoPathsObserved`: actual input-error/catch/finally and output-error/
  cancel paths were observed. It proves no after-return or native resource count.
- `coverageComplete`: those paths plus both safe tagged inspections. Changed or
  discarded factory/unknown failed export remains inconclusive.
- `collectorAccepted`: all of the above. Only this yields raw0. A valid retained
  inconclusive observation yields raw1, with its complete data preserved.

The current adapter rethrows output failure, so observing its desired error path
can leave safe inspection unproved. The collector preserves that distinction
instead of accepting a known gap. `Request.signal` has no peer link in this
baseline; its actual value is retained, not counted as Node parity. There is no
instant idle-abort promise, HTTP trailer completion, native disposal/root count,
Store-death cleanup, physical Store identity, same-Store overlapping HTTP,
full-Next/adoption or snapshot/reset claim. Root's later runtime grant must keep
this scope explicit.

Pure DATA checks cover missing success markers, finally-on-rethrow, changed
identity, attempts without returns, closed versus actual I/O failure, unknown
errors, no write failure, incomplete schema and normal control payloads. They
instantiate no guest/resource/transport objects and prove no runtime behavior.
