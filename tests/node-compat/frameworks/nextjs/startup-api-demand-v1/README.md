This is a source/API-demand inventory for the real Next 16.4.5 standalone app that passed the retained Node-host Module/HTTP bridge run. It is ready for implementation planning, not guest or native admission.

All **406 recorded compilation inputs (4,439,412 bytes)** parsed with the pinned Rolldown 1.2.16/Oxc parser under Node 22.14.0. The actual run recorded **40 builtin-load spellings**; the bounded alias/scope analysis resolved **78 API paths**. Its raw command exited 0 with empty stderr. No application module, server, target engine, guest or native compiler ran during this inventory. The parser's host native binding was loaded for parsing. Host builtin imports below only inventoried export names; no exported method was called.

The retained host result passed 24 HTTP and two browser checks, including five streaming chunks and cache invalidation. Its provider used real **host** Node FS, compilation, globals and builtins. Compiled-file membership proves a file reached the host compiler; builtin loads prove a name was requested. Neither records which method calls or conditional branches executed.

The immediate source requirements are:

| Area | Concrete source requirement | Implementation boundary |
| --- | --- | --- |
| process / os | Mutable env, guest cwd, process event methods; default config evaluates `os.cpus()` unless `CIRCLE_NODE_TOTAL` short-circuits it. | Standard CLI environment can provide env/args/cwd. WASI 0.2.10 supplies no host CPU topology/NIC/RAM inventory. Choose truthful virtual-resource semantics or explicit refusal; do not fabricate host facts. |
| timers | Next captures and then patches `process.nextTick`, global immediates, `node:timers` and `node:timers/promises`. It uses `util.promisify.custom`, Immediate ref/unref/hasRef/dispose, cancellation and ALS capture. | Implement actual queue ordering and native task ownership. A Promise or `queueMicrotask` alias does not establish Node nextTick semantics. Timer objects/modules must allow the actual patch. |
| URL | Global URL/URLSearchParams, `URL.canParse`, legacy `url.format`, and file URL conversions. | Reuse actual WHATWG URL; implement legacy formatting and file-URL validation. No attributable **node:url.parse** call was found in this cut: Next's own `parseUrl` uses URL/parseRelativeUrl. Legacy parse/resolve/urlToHttpOptions remain broader compatibility work, not observed calls. |
| HTTP(S) | Startup constructs both Agents. The real handler needs request/response headers, bodies, status, abort, drain/finish/close/error and streaming. | A standard `wasi:http/incoming-handler` bridge can run the unchanged handler without guest TCP listening. Agent/outgoing fetch behavior still needs genuine implementation. Deferred `startServer().listen()` is a different path. |
| compression | Actual webpack module 106 is node:zlib; middleware selects `createGzip`/`createDeflate`, calls flush/write/end, and connects pause/resume to response backpressure. Close cleanup recovers a Duplex and calls destroy. | A real native-backed Transform with bounded state, errors and exactly-once cleanup is needed. Existing finite sync codecs do not provide streaming. This exact middleware has no Brotli or `Z_SYNC_FLUSH` token. Conditional cache serialization separately requests sync codecs plus base64/string Buffer support. |
| performance | `performance.now/timeOrigin`, `process.hrtime.bigint`, and guarded `performance.measure`. | Use actual wall/monotonic clocks and correct origin/measurement semantics. `perf_hooks` was not a recorded builtin load here. Current global now/timeOrigin is not evidence of measure or epoch/snapshot correctness. |

Citations include file, line, byte offset, token, snippet and input SHA. Minified webpack/numeric module joins for compression are explicitly supplemented in recommendations; the analyzer does not solve arbitrary wrappers, dynamic properties or all numeric module graphs. Parameter/prototype demand such as ServerResponse is manually cited. It is not a complete capability closure or a static sandbox proof.

A first curation authoring command failed a literal-token lookup before writing an output; the retained `curate.py` then checked actual tokens and succeeded. The AST/parser pass succeeded on its first attempt. Production source, accepted profile versions, staged/frozen artifacts and existing results were unchanged. FS, ALS, Module native frontend/linking, Buffer.concat, util.format, crypto/RNG/WebCrypto and complete unchanged-app guest validation remain separate work. No subset SSR success or host-only run substitutes for that full-app goal.
