# Portable installed-generator checker V1 — Source only

This is a new generator-only producer, not a build or an old-result retarget. It reuses the exact ten installed `--check` command arguments from `native-profile-candidate-v1/check-installed-v7.py` (aa6aa73c), including `--crypto-random` and sync zlib's required `--repository`. The historical cbc1 result remains bound to its original V7 root and is never accepted as this root's proof.

Default invocation prints the Source command plan and does not launch anything:

```sh
python3 -I -B run.py
```

A future public launch requires a separately issued Root document:

```sh
python3 -I -B run.py --authority /ABS/issued-root-authority.json
```

The template is unissued and unusable. Source, plan, prepared selection and permissions must be concrete; output/argv/environment overrides are refused. Root selects a safe1–48 ASCII runId. Outputs derive exclusively from the fixed `next-native-portable-generators` prefix and are fresh siblings of the materialization, with a separate `-external-root` monitor directory. No source tree, SDK, tool, app or binary is copied.

The producer pins the held materializer and R's admission Source eaf4/portable.py dfb0/policy dfaa. Before any custom import it authenticates complete indexed membership and descriptors. It invokes the actual read-only `admit(selection_ref, policy, repo)` before/final and before each command. That authenticates the retained825 files, exact435/387/3 roles, modes, fingerprint47755843, source-only composition7db733 and whole physical file/directory identities. Native435 descriptor arrays remain separate from825 physical records; this is not compiled metadata.

The original0af six-argument monitor owns each Node check with its original30s bound. A second original0af900s monitor owns the complete collector. Each command retains actual `started.json`, terminal, complete stdout/stderr and a typed record **before** assertions. Raw1, stderr, timeout, signal, interruption, cleanup uncertainty or source change fails and stops further commands. An exceptional monitor call retains all physically available records with unknown fields null; it never invents a successful exit. Final source/tool checks run independently of command success. No generator factory, native crypto kernel, engine, guest, CMake, Cargo or compiler is invoked by the check commands.

The worker writes `body-result.json`. Pre-action authorization/admission failures may precede outputs; an owner-observed worker failure may produce a genuine failed envelope with a missing body, never a usable receipt.
