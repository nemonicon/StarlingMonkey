# CommonJS `.cjs` file-URL interop — stopped uncompiled prototype

This is a later one-TU Source descendant of the sealed `5e7b07a6` guarded loader (`fbc1d13e`, 22,292 bytes). It does not modify the guarded materializer/build route, repository runtime, JavaScript facades, CMake/Rust inputs, host or WIT. The afterimage is uncompiled. No import, engine, HTTP, Node oracle, GC/OOM/fault/reset or native action was run. Six anchored Source transformations reverse to the exact guarded parent.

The new path uses the existing common `NODE_COMPAT_MODULE` macro. Actual `cmake/builtins.cmake:437–439` already requires FS whenever Module is selected; FS and startup macros are private to their builtin TU and do not appear on the genuine loader compile row. The private FS header uses a finite relative include from `runtime/`. In a Module profile without startup/URL registration, missing private callbacks produce an explicit refusal. No CMake flag is added. The unchanged VM-data and builtin paths precede this branch; the guarded generic fallback and metadata/builtin wrappers remain unchanged.

## Selected contract

- Only canonical local `file:///...` URLs to existing regular `.cjs` files are selected. A lexical `fileURLToPath` / `pathToFileURL` round trip must preserve the exact URL string. Uppercase schemes, local-host spellings, query/fragment, encoded `/` or `\`, decoded NUL, noncanonical spellings, other extensions and non-JavaScript module request types refuse. Malformed URL/escape errors from genuine URL callbacks propagate as produced. This is a bounded profile, not complete Node URL/ESM resolution.
- `next_fs::check_deployed` precedes callbacks, cache access and filesystem operations. `stat_path`/`realpath` use the existing standard-P2 preopen provider, then the real require.resolve result must equal that canonical `.cjs` filename. Paths are bounded by the existing 4,096-byte provider limit; encoded URL input is bounded at `3*4096+8` bytes. No libc path or guessed capability prefix is introduced.
- Original `node:module.createRequire`, `node:url.fileURLToPath`, `pathToFileURL` and native `URL.prototype.toString` functions are captured into private traced roots during actual builtin registration, before application code. Capture accepts own DATA callables from the content realm, never invokes public getters or calls a callback during INIT. Public method replacement cannot replace these captured functions. The genuine Module closure still consults its mutable require/cache/extensions hooks, which Next uses.
- The ephemeral real require and its real resolve function perform CommonJS loading. Own-data inspection of its genuine cache rejects in-progress/malformed/cross-realm records. After require succeeds, the completed cache's exports value must be `JS::SameValue` to the returned value. Objects/functions preserve reference identity; primitive values, including undefined, NaN and signed zero, are accepted by this identity operation. No export properties are enumerated or read.
- `JS::CreateDefaultExportSyntheticModule` creates a real single-default module. The existing PersistentRooted `moduleRegistry` retains it under a private NUL-tagged canonical URL key, distinct from builtin and ordinary filesystem keys. Canonical symlink aliases use the same final URL key. The namespace contains a default binding to the successful require value, with no invented named exports, `__esModule` or namespace `then`. The returned export's own `then`/getters are not inspected by this loader.
- At most 8,192 successful new namespace records are published. A nonallocating RAII busy bit refuses **all** nested file-URL loads, including different targets and cache hits; it is not a native task/resource identifier. Its destructor only clears the bit, preserving pending exception/status on every failure path. New namespace count and private roots initialize with the existing loader's single-runtime lifetime.
- Current realm, request object, private callbacks/cache records and object-valued exports must belong to the engine content realm. Cross-compartment wrappers/cross-realm object exports refuse. Primitives require no object realm conversion. This is explicit refusal, not wrapping or cross-realm interoperability.

The original referrer/request/payload reach `FinishLoadingImportedModule` unchanged. The new code does not call `SetModulePrivate`, `GetModulePrivate` or an import.meta hook for a synthetic record; the pinned implementation has no script/source-private slot for that record. No generated JavaScript wrapper/source or extra Map is added. The new module itself traces its environment's default value; temporary values, methods, argument arrays and modules are rooted across allocation and calls. Native encoded/canonical path buffers own their bytes across JS calls.

## Errors and deliberately incomplete parity

Profile refusals create a native TypeError with own DATA `.code = 'ERR_SM_MODULE_FILE_URL_UNSUPPORTED'`, actual `.module` specifier (undefined when unavailable during capture), and `.operation`. New error annotation uses the parent's genuine `AutoSaveExceptionState` pattern: preserve an existing pending error, keep reporting OOM, drop the saved diagnostic on annotation failure, restore only successful annotation. Genuine URL, filesystem, require/resolve, JSAPI, thrown primitive and uncatchable failures return directly. No truthy/falsy error normalization is added.

A target that throws is not published as an import namespace; its original Module loader performs its existing failed-load cleanup. **Rejected imports are not cached here.** Repeated throwing-target behavior therefore has no Node error-cache parity claim. Successful namespace default values remain snapshots of the first successful require result; later object mutation is visible through the same object, but `module.exports` replacement or require.cache deletion does not replace a cached namespace. The prototype revalidates current filesystem paths before finding the namespace cache, so deletion/replacement and symlink-race behavior is not full Node ESM-cache parity or race-free file identity.

Only `GetModuleRequestType` is inspected. Non-JavaScript types refuse; unknown import-attribute-key semantics remain the engine's existing behavior and are not claimed to have been separately validated. Static imports may reach this same hook too; this prototype does not claim a dynamic-only API switch. `.js` package-type handling, `.mjs`/npm ESM, JSON/addons, import maps, CJS named-export analysis, live bindings, arbitrary require-hook retargeting/proxy cache behavior and cross-instance cache sharing are deferred. A require hook that returns another value or does not retain a completed matching cache record refuses rather than publishing an invented wrapper.

Next's consumer must separately be exercised with a real `.cjs` cache handler after the guarded native build and a later reviewed interop build. Its own `mod.default || mod` Promise callback can intentionally assimilate a thenable export; this loader does not promise arbitrary thenable cache handlers. Import support alone cannot repair the observed multi-epoch module-local counter or prove cross-request cache coherence. Earlier cache/browser failures remain failed.
