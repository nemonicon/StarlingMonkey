A minimal future design would keep the following constraints:

- Define one opt-in native JS function in the embedding translation unit. Enter the existing content realm and root the new record/function/value during registration, as the actual Node install does. The proposed signature is primitive-only: fixed method/path/state/count enums and a primitive64-lowercase-hex string or null. Its final module/function names are not selected here. No Request/Headers object, property lookup, conversion hook, callback, exception object or arbitrary input text reaches native inspection.
- After the existing guest Request/correlation snapshot, the separately versioned guest could call that function synchronously at the genuine adapter-entry site. It must not add an await, reader, body operation, header, timer, entropy, expected manifest or ownership change. Registration can allocate at INIT, but callback/stdio/manifest observation cannot run at INIT. An inactive/deployed-state gate would return an unavailable observation without logging or changing application results.
- Store only fixed C++ bytes/enums/counts, with no retained `JS::Value`, `JSString*`, object, borrowed character pointer or JS callback. At runtime use `CallArgs` primitive type checks and a local `JS::RootedString`. For a64-unit **already linear** string, the pinned String.h provides the infallible `JS::CopyLinearStringChars` path; copy into stack storage under a no-GC scope, validate every hex character, then copy owned bytes into the native buffer. A rope/nonlinear string is unavailable, not flattened to force a result. `JS_GetStringCharAt`, `StringToLinearString`, UTF-8 encoders and JS allocation are not assumed infallible.
- Reject invalid diagnostics by marking unavailable/ambiguous, not by reporting a JS error or coercing input. Do not use AutoSaveExceptionState as a blanket way to clear a new OOM/uncatchable status: its documented conditional destructor and explicit restore/drop behavior do not provide universal no-throw semantics. Avoid fallible JS APIs in this runtime callback. Ordinary metadata failures can be isolated; engine traps, OOM and host I/O traps cannot be promised harmless.
- Activate one fixed buffer only inside the real native call window. Each observation increments a saturated available-snapshot count. More than one observation makes the call ambiguous even when values match; do not select the first/last. Missing/invalid/duplicate correlation also stays unjoined. Keep a checked component-local export counter only as descriptive state, never a globally unique ID. No JS current-global, ALS change or numeric-ID join is introduced. An observation while a native window is active does not independently prove which prior callback scheduled it; multiple/background/reentrant observations cannot manufacture request-origin identity.
- After the existing successful loop/strict-rejection/fulfilled-state checks **and** existing result lowering, a proposed bounded record immediately before `call`'s return could copy that single public value into standard stdout. Call it a native success-return **site**, not a completed C return, completed canonical post-return or host task. No extra Promise reaction, JS invocation or loop-interest change is needed. This is a new ordinary legal-call I/O operation and can block or perturb timing. It must check partial writes/flush failure conservatively without masking application errors.
- Preserve the existing nesting guard, Promise roots/reactions, returned bits, allocator/free-list operations, failure/abort branches and all function signatures. Clear current diagnostic membership at the real retirement path. No silent overwrite, guessed reset, GC/finalizer operation or extra host HTTP request is proposed.

Direct post-return logging is excluded from this design. One possible *separate, unselected* alternative is a fixed memory-only post-call flag/record, copied after the existing free-list clear and flushed on a later legal native call before clearing it. It needs a distinct pending-record ownership/overflow policy. No later call means no observable final record, and a different instance cannot flush it. A later record would prove only that a prior memory site was reached, not the host's successful canonical return. Do not force an extra request or treat missing flush as failed cleanup. This alternative remains deferred; it is not an implementation recommendation or substitute for a last-call observation.

The current build already compiles embedding.cpp as the separate `builtin_componentize_embedding` target through ComponentizeJS CMake `add_builtin`; the actual command enables internal ticks, ALS, strict initialization and runtime-only entropy and uses `-fno-exceptions`. A future diagnostic macro must be a new explicit default-off target definition, not DEBUG, an environment flag or an assumed existing option. Embedding-only state/registration can stay in embedding.cpp; no cross-translation-unit ABI hook is needed. A separate engine rebuild and fresh full metadata/admission/constructor are still required. Keep the same13 standard interfaces and incoming-handler export as a requirement, then inspect the genuine complete returned import list; do not project the old131 function count.

Before any implementation, the remaining choices are the optional internal builtin surface, exact primitive validation/string-unavailable policy, per-call ambiguity/clearing rules, ordinary-call stdout error behavior and Source-controlled build flag. A normal-input validation plan would test the actual primitive callback with valid/missing/invalid/duplicate/rope/multiple snapshots, bounds and inactive INIT; then a fresh normal component/full-suite run with all existing gates and the bounded raw stdout owner unchanged. Those are future tests, not results here. There is no native patch, build, prototype API call or runtime grant in this proposal.
