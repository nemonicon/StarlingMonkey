This unexecuted Source diagnostic adds Chrome NetLog capture to the held `22ed` strict browser worker. It preserves both tests, their whole 20-second deadlines, normal CDP sessions, action/body/finished/sizes observations, screenshots, and every original error/assertion gate. It uses the same Playwright isolated profile. No JS fetch/Response wrappers, abort injection, navigation changes or application changes are introduced.

The only added Chrome arguments are `--log-net-log=<fresh private output>/netlog.json` and `--net-log-max-size-mb=16`. No capture-mode argument is supplied: Chromium documents the default as stripping private information. Its [capture instructions](https://new.chromium.org/for-testers/providing-network-details/) document both startup flags. No raw browser-wire or sensitive-header completeness claim follows.

After the unchanged normal browser close, the worker checks the file's identity and its 20 MiB final-file ceiling, sets mode 0600, fsyncs it, requires complete UTF-8 constants/events JSON, and records its exact digest. Oversize or malformed data is never truncated, repaired or regenerated; it remains a diagnostic failure. The requested circular 16 MiB event cap and the 20 MiB read ceiling are separate. Chromium's [NetLog design](https://www.chromium.org/developers/design-documents/network-stack/netlog/) explains that bounded captures overwrite earlier fragments and stitch them after capture. Complete JSON therefore does not prove a complete event history.

`analyze.py` is a separate read-only Python DATA tool. It uses the captured constants, selects only an event explicitly recording URL_REQUEST, the exact leased `/actions` URL and POST, then retains events from those sources and one explicit dependency hop. It reports explicit net errors and original indexes/time strings. Missing or evicted witnesses remain unobserved. Its expected constant-table names also match the [primary Chromium implementation](https://chromium.googlesource.com/chromium/src/+/HEAD/net/log/net_log_util.cc); this reference is a format witness, not a binary-source attestation for the installed Chrome. Actual captured constants control decoding.

NetLog source IDs are local log roles. They identify neither WASI Stores nor native resources. The analyzer aligns no NetLog/Node/Playwright/CDP clocks and proves no unique cause, full request lifecycle, browser equivalence or Next acceptance. All prior browser/cache failures remain failed. The 26 synthetic Python checks and two AST reads evaluate no JavaScript; actual capture, runner authority and runtime results remain null. B authored this fork and analyzer and previously authored related Source bindings.

Explicit negative net codes remain neutral observations. The primary [Chromium error list](https://chromium.googlesource.com/chromium/src/+/HEAD/net/base/net_error_list.h) describes IO_PENDING as asynchronous completion pending rather than a fatal error; the analyzer makes no terminal-failure deduction from negativity. Stat bookends exclude access time, and the worker rechecks its final size ceiling immediately before reading.
