# Classic streams: current dependency and port boundary

This is a **source-only supplement** to the preserved [original audit](../../foundation-stream/README.md). It installs no classic-stream module and runs no guest, native build or performance test. The latest accepted checkpoint is [v11](../../milestones/foundations-v11/README.md); the current private-tick source layer is applied but has no successful diagnostic engine publication/runtime acceptance. Ordinary Node-host reference cases below are oracle evidence only.

[source-audit.json](source-audit.json) verifies the current **306-input** native policy against live bytes and its accepted 304-input v11 ancestry: five changed files and two new queue files. It pins 88 repository/locked-package inputs, six external Jco/ComponentizeJS sources/tests, 29 Node22 embedded source records, 241 literal package dependency edges and 121 demand sites. The reachable `readable-stream/lib/stream.js` core is 24 files. No source tree is copied or modified. Source comments carrying historical “unapplied” wording do not override the actual hash/adoption state.

The compatibility pin remains **Node v22.14.0**. Locked dependencies are Jco1.40.0, ComponentizeJS0.23.0, Jco-std0.10.0, readable-stream4.7.0, unenv2.0.0-rc.24, buffer6.0.3, events3.3.0, process0.11.10, string_decoder1.3.0 and abort-controller3.0.0. Package paths and hashes are recorded; no npm package is installed by this work.

## Exact inventory and identities

[proposed-api-boundary.json](proposed-api-boundary.json) derives the 33 export rows and each constructor's own string/symbol inventory from the actual pinned runtime. All three classic namespaces are currently **unavailable**; planned partial/import-only statuses describe a future explicit contract, not current support. Untested executable methods are not promoted merely because an inherited method exists. Nonregistry symbols are reflection observations, with no portable API identity inferred from descriptions.

| Namespace and proposed bare alias | Exact ESM names |
| --- | --- |
| `node:stream` / `stream` | `Duplex, PassThrough, Readable, Stream, Transform, Writable, _isArrayBufferView, _isUint8Array, _uint8ArrayToBuffer, addAbortSignal, compose, default, destroy, duplexPair, finished, getDefaultHighWaterMark, isDestroyed, isDisturbed, isErrored, isReadable, isWritable, pipeline, promises, setDefaultHighWaterMark` |
| `node:stream/promises` / `stream/promises` | `default, finished, pipeline` |
| `node:stream/consumers` / `stream/consumers` | `arrayBuffer, blob, buffer, default, json, text` |

Node's root default is the callable `Stream`, and `Stream.Stream === Stream`. The six constructors form real classic EventEmitter/read/write state machines. `stream.promises === promises.default`; callback pipeline/finished have `util.promisify.custom` getters returning the matching promise functions. Preserve these initial identities and Node's mutable default graph, while documenting named ESM bindings as installation snapshots without `syncBuiltinESMExports`. Literal static CommonJS lowering must return the correct default callable/object; no runtime CommonJS loader is implied.

There are six further real legacy IDs: `_stream_readable`, `_stream_writable`, `_stream_duplex`, `_stream_transform`, `_stream_passthrough`, `_stream_wrap`, each with a `node:` spelling. The first five default-export the corresponding constructor, but their named ESM sets differ: `_stream_readable` includes `ReadableState,_fromList,from,fromWeb,toWeb,wrap`; `_stream_writable` includes `WritableState,fromWeb,toWeb`; `_stream_duplex` includes `from,fromWeb,toWeb`. The remaining two export only default. Do not admit these via a universal alias map. `_stream_wrap` is deprecated and delegates to `internal/js_stream_socket`, whose native `stream_wrap`/`async_wrap` dependencies are separately recorded; it remains deferred. No Node22 `stream/iter` or consumer `bytes` exists.

Node exposes no global `Stream`, `Readable`, `Writable`, `Duplex`, `Transform` or `PassThrough`. The proposal adds none, and adds no public `process`. The existing selected native `node:stream/web` remains a separate bounded dependency. It is **not** a replacement for any classic constructor, EventEmitter graph, callback protocol, state accessor, or backpressure algorithm.

## Concrete adapter findings

The existing Jco `createStreamBuiltin` resolves internal readable-stream dependencies to shared Buffer/events/StringDecoder and a private scheduler. It is useful bundler precedent, not a Node22 implementation oracle. Its importer-scoped rewrites matter: `process/` and `string_decoder/` are npm requests, not approved native aliases. Jco's extra `stream/iter` and consumers `bytes` must not enter this pin's manifest.

`readable-stream4.7.0` is an MIT Node18.19-derived core. Select its explicit `lib/stream.js` graph. Its package main reads `process.env.READABLE_STREAM`, requires `stream` and may choose the host implementation; its browser/default wrapper is Readable, not Node's Stream. Jco-std layers Node24.20-derived lifecycle/pair/Web changes, so copying that layer wholesale would change the compatibility baseline. Its `callableEmitter` constructor Proxy and global emitter-prototype mutations adapt an unenv ES class; they are unnecessary for the already callable installed EventEmitter and should not be adopted.

The core has exposed but nonworking `fromWeb/toWeb` functions: `lazyWebStreams()` returns an empty object. These must become finite explicit refusals until a real bridge gate, rather than retaining accidental property-call TypeErrors. Unenv's standalone Stream default is an object and its lifecycle/promise/consumer operations include stubs. It supplies neither the required default graph nor a coherent stream state machine.

The package's `ours/primordials.js` is a simplified shim that still dynamically calls operations such as `self.slice/map/pop` and `fn.call`. It is not Node's captured-primordial contract. `ours/errors.js` also assigns fields such as `AbortError.this.code` and aggregate error fields. The port must audit captures and create its own profile/error fields with captured `defineProperty` and null-prototype descriptors; no broad primordial immunity follows from reusing this package. This is source evidence, not a native error-poisoning probe.

Inspected [Jco tests](https://github.com/bytecodealliance/jco/blob/jco-v1.40.0/packages/jco/test/node/stream-classic.ts) exercise core aliases, operators, pipeline/flush, byte views, pair/disposal and Web conversions on their own adapters. They do not certify our different native Buffer/emitter/scheduler, caps or optional admission. ComponentizeJS's existing HTTP fixture uses low-level WASI input-stream reads (and says “TODO: actual streaming”); that is a resource binding example, not a Node classic-stream adapter. The published readable-stream package excludes its upstream tests. [primary-tests.json](primary-tests.json) pins the exact Node22 consumer and pipeline test sources inspected; neither full upstream suite was executed. Their HTTP/net/timer branches require separate resource capabilities and must not be silently included in a capability-free test selection.

A future installer can root that function in the content realm and pass it to the strict existing `evaluate_factory`, alongside shared Buffer/EventEmitter/addAbortListener/StringDecoder/Abort constructors and selected symbols. Rewrite the core's literal `process.nextTick` demands to the captured callable and explicitly remove only its host-stdio sentinel comparisons under the no-stdio contract; do not synthesize environment, platform, PID or process behavior. No diagnostic module ID belongs in production.

## Minimal coherent sequence

1. **Close the existing tick runtime gate first.** Reuse its exact finite diagnostic protocol, not another ALS investigation. Preserve complete Promise checkpoints and origin-sensitive tick order, limits4096/1024/65536, rooted callback/args, and fresh-instance discard after fatal failures. Reset cancellation/reentry remains OPEN; queue emptiness alone is not a reset/reuse proof.
2. **Prepare one licensed pure classic core factory.** The first coherent gate covers real Stream/Readable/Writable/Duplex/Transform/PassThrough; ordinary object and fixed attached unshared byte modes; UTF8/hex; read/push/unshift, write/end, pause/resume/pipe, cork/writev, construct/final/flush, destroy/error/close, backpressure and default/accessor graph. Include callback `finished/pipeline` and the shared promise namespace, with cancellation/cleanup/error/return identity tests. These are core lifecycle mechanisms, not Web wrappers.
3. **Apply exact Node22 deltas and finite API policy.** Node22 accepts all ArrayBuffer views with byte offsets, has the POSIX64KiB/16 defaults, `duplexPair`, Writable async disposal and selected ownership/reflection changes. The source inventory also exposes readable-stream's extra `asIndexedPairs`; do not export it as Node22. Pair, pure operators/iteration/compose, state predicates and disposal remain explicit next gates, not permanent stubs to save effort. Unsupported Web/Blob/encoding/legacy overloads need identifiable own-coded call/new failures. No universal Proxy or accidental thenable namespace.
4. **Bound resource behavior before admission.** HWM is a threshold, not a memory cap; applications can ignore false writes/pushes. Propose at most16MiB queued bytes and4096 queued chunks per relevant side, with separate object-count/work accounting and the existing tick bounds. Exact values and pre-mutation/atomic-failure behavior are OPEN engineering decisions, not implemented guarantees. Arbitrary object payloads and application callbacks cannot be given a total memory/CPU bound by chunk counts. Scheduler-limit failure/partial stream state needs an explicit discard/recovery policy and tests.
5. **Install optional manifests only after the pure gate.** Use existing `add_builtin`, strict factory/header generation, finite real records and `define_builtin_module` for six core/promise/consumer IDs and bare aliases. Default-OFF feature selection must require actual compiled dependency flags and keep capability imports unchanged. Generalize the existing manifest-first resolver so explicit native selection wins over Jco/unenv/npm replacements, and reject unknown/deferred IDs. New flags/recipe/source ancestry need a new finite admission policy; this packet changes none.
6. **Advance consumers and bridges independently.** Reuse text/json and the existing bounded Web iterator. Finish Blob ownership/semantics before arrayBuffer/buffer/blob; preserve parts through final construction. Add true classic-to-Web/from-Web adapters later, including locks, transfer/copy, error/cancellation, half-close, backpressure and options. Inspection predicates/finished must not acquire a reader and change a lock as a side effect.

Future ALS must capture the existing [resource-model-v3](../../async-context/resource-model.md) cell/owner at enqueue and restore it around the callback through the actual audited hooks. Current tick entries trace only callback/args. Do not wrap `Promise.then`, expose a generic global context, or claim Node async_hooks. Request cancellation and owner/reset teardown remain separate gates. Application-owned pure stream objects might legitimately survive a snapshot; empty queues do not prove their state or external resource safety. Keep explicit snapshot/retained-instance/fresh-host vectors and no live WASI handles in this pure profile.

## Validation and evidence limits

[node-results.json](node-results.json) ran the preserved11 ordinary Node groups plus six small supplemental groups under the exact pinned binary. The direct readable-stream comparison uses **Node's own host dependencies**, not the proposed native guest injections. It records two concrete differences: DataView write is accepted by Node, preserving buffer/offset1, while readable4.7 rejects it with `ERR_INVALID_ARG_TYPE`; byte defaults are64KiB versus16KiB. Small multi-chunk aggregation and split UTF8 examples agree. Reflection-only deltas include missing root `duplexPair/_isArrayBufferView`, missing Writable async disposal, extra Readable `asIndexedPairs` and selected own-property differences. None of this establishes other methods' behavior.

Future actual-component gates must pin every factory/transformation/license/dependency source before and after, use the selected native module registry and shared class identities, audit zero imports, and run Node differential ordinary domains, queue/encoding/error/cancellation limits, unsupported call/new and initializer failures, raw uncached dynamic imports, named/default/static-CJS aliases, snapshot and repeated/fresh execution. Release-GC checks must isolate queue-only callback/argument ownership. Reuse the preserved scheduler drift,11Node groups, consumer18/12 groups and m0.9 iteration corpus; do not recast their earlier results as a new candidate pass. Use stock Wasmtime/wasmCloud only after the pure component gate and inspect exact emitted interfaces.

No capability is selected here: `[]`. Pure streams and ticks need no clocks, environment, DNS, sockets, filesystem or HTTP imports. Future real resource streams must select their standard WASI0.2.10 interfaces/type closure separately. WASI IO resources are not Node stream classes, sockets do not provide TLS, and no custom host service or host modification is proposed. No size, startup, memory or throughput benefit is claimed; measure the final state-machine/facade on the same frozen engine/packager/host before moving additional copying/control into native guest code.
