No classic-stream performance measurement has run. This proposal embeds roughly 205 KB of generated guest JavaScript plus its facade and source/header representation. Native byte codecs do not imply that stream scheduling, queue bookkeeping or the captured state machines are native.

After correctness and actual-artifact admission, measure two questions separately. For throughput, use the same reviewed classic-enabled engine and identical native Buffer/Events/StringDecoder/private queue, then vary only whether the application calls the registered classic factory or a licensed portable JS state-machine bundle with the same bounded semantic changes. This measures the binding/packaging path with the installed factory cost common to both arms; it cannot establish that enabling the feature is free. For component size/startup/retained memory, compare the reviewed enabled and disabled engines with the respective equivalent application bundles, recording the source/flag difference explicitly. That is a whole-profile comparison, not a single-kernel causal claim.

Use valid public API workloads after matching Node22 checksums and event-order outputs: 64-byte and 512-KiB byte chunks through Readable→PassThrough→Writable; fragmented UTF8 through StringDecoder; object-mode high-water-mark/backpressure; and bounded pipeline cancellation/error completion. Distinguish zero-copy views from `Buffer.from(existing Buffer)` copying construction; none of these workloads measures the deferred `Buffer.prototype.copy` method. Keep all queue limits below their declared bounds and report output equality before timing.

Pin the same packaging splicer, adapter/features, host executable, CPU/thread settings, warmup, input bytes and batches. Use alternating arm orders, at least three fresh instances and seven timed batches per scenario. Record component bytes, snapshot/componentization time separately from deployed startup, Wasmtime peak RSS, requested linear-memory bytes and operations/bytes per second. Preserve raw samples, instance/batch counts, runtime import/export audit and all engine/application hashes. An HTTP host has separate transport/instantiation effects and must not be treated as proof of retained-instance reuse when observed request counters remain one.

Promote a cost claim only for the measured operation and pipeline. Existing Buffer measurements, Node-host differential tests, SDK syntax success and synthetic metadata tests establish no classic-stream throughput or memory advantage.
