## Intake and marker interpretation

1. Read/authenticate the final cohort/owner records and each trial result/capture metadata before reading raw stdout. Preserve original application verdict and raw exit separately from ownership cleanliness. A clean raw 1 semantic failure remains a failed application sample, while a complete raw capture can still provide diagnostic data. Verify actual actor index, selected entry/INIT review/component, runId/namespace and source roles from each genuine trial; do not retarget old artifact arrays.
2. A native stdout is eligible for complete marker analysis only when its published capture proves pipe EOF, all accepted writes finalized, sync/close and final path/size/hash bookends, no overflow/errors, and the existing 8 MiB bound. Child exit alone is not pipe EOF. Interrupted-client descriptors remain subject to the original monitor's descendant authority. Incomplete prefixes remain retained, explicitly **incomplete/unretained-unknown** beyond their recorded bytes; never infer absent markers from them or manufacture a final digest/quiescence claim.
3. Read each complete native stdout once with size checked before read, hash/length authentication and physical read bookends. Preserve every byte and ordinary line before interpretation. Standard `--no-logging-prefix` is already in the authenticated native actor; do not silently remove a guessed host prefix. Any unexpected prefix/format is retained and reported, not normalized into an invented marker.
4. A/B have no response logger. Their marker result is **not applicable to selected Source**; explicitly count any unexpected response/Promise marker family without attributing it to an arm's private handle or accepting a mismatched Source. Zero records establishes no completion, lost-log, Promise or host fact. Stock controls likewise have no guest marker expectation; do not fabricate a Wasmtime stdout for them.
5. C/D use the exact inherited response record schema. Validate duplicate-free JSON, known marker/version, complete ASCII record at most 512 bytes including LF, allowed fields/types, safe-integer counters, admitted GET/POST `/actions` or GET `/action-result`, lane/event/phase and flags/caughtType. Logger error/truncation frames have their shorter reserved schema. Keep ordinary lines, malformed marker candidates, partial lines, foreign marker families, explicit errors and truncation separately. Parse success alone does not establish complete diagnostic observations; logger failure may prevent its own error frame. Do not assume any event or request count, including earlier six-per-site patterns.
6. Produce source-site aggregate counts and descriptive partitions per trial, route/method, lane, event/phase/flags. Count sequence/token collisions and missing/malformed/logger records explicitly. Sequences and lane tokens reset per component snapshot and may collide/interleave across instances; numeric partitions are never physical identities, even if no collision is detected. Do not concatenate equal IDs into a handle, infer classic-to-adapter or POST-to-self-fetch joins, or use path/order/bytes to invent those joins. Any order shown must remain explicitly descriptive unless its logical Source trace is independently unambiguous; it still proves no physical realm identity.
7. Interpret positive sites narrowly: `adapter-read-eof` is the existing reader's done branch; readBytes/readChunks are returned-reader data, not written/peer bytes. Child-dispose/OutgoingBody.finish-return markers prove only return at those public call sites. Finish-return precedes original finally/guards. Post-cleanup records the Source flags at the reached site; normal-return-site is fallthrough after unchanged guards, including permitted handled-closed paths. Neither is child/neutral/export Promise settlement, native event-loop/post_call, private resource retirement, host task completion, TCP EOF or browser completion. Explicit adapter-catch is an observed Source-phase exception type/null, preserving the original value; missing sites remain unobserved.

The final comparison table should have ten immutable ordered rows: trial/block/arm/runId, actual component/entry/review, original owner/raw/semantic verdict, capture status, marker applicability, bytes/hash/ordinary lines, event counts, error/truncation/malformed/collision/missing qualifications, and links to C/B outcome/owner evidence. Preserve all original 52/80/24/cache/stream/browser gates, including each actual failure. Do not turn marker parse success into an overall pass. A/B's absent logger cannot be a denominator for C/D marker-rate comparisons. Two exploratory samples per arm and logging/await scheduling perturbations establish no reliability estimate, unique cause, private identity, production acceptance or fix.

## Proposed offline retained corpus

After all required records/reports are genuinely held, curate one finite manifest with ten ordered trial sections plus a cohort section. Derive exact allowlists/counts/bytes from authenticated final records; do not reuse earlier corpus sizes or owned-record counts. Plain independent copied files are sufficient; no new archive/controller framework is needed.

- Cohort: fixed plan/policy/driver/launcher/preparer and bindings as finite Source witnesses; genuine cohort authority/preparation/result and complete original 7200-second monitor records/streams. Preserve explicit unattempted/invalid entries and their existing reasons without manufacturing trial monitors/results.
- Every attempted trial: actual authority/result/observation, complete original 300/600-second monitor directories/owned snapshots/streams, genuine before/final native/world receipts, and retained raw client observations. Keep complete actual client file namespaces (raw five cases, original HTTP/concurrent/stream/browser data, body/assets/PNG and full NetLog) with manifest role joins; no favorable-record selection.
- Every native trial: exact finalized or explicitly partial Wasmtime stdout, its complete capture metadata and Wasmtime stderr/shutdown evidence. Retain entire bytes before any marker-derived JSON. Apply the existing per-file 8 MiB stdout and 20 MiB NetLog read bounds; set a finite corpus aggregate/read budget from the finalized allowlist and authenticated sizes before replay. No unbounded scan/read or silent truncation.
- Provenance: all four selected entry witnesses/indexes, the shared B/D map, inherited marker schema with D qualification, actor indexes/plans/helper, genuine INIT/full-build/app review descriptors, and eventual C/B/R DATA reports once held. Deduplicate a copied original only by exact descriptor while retaining every trial role. Do not prebind hashes of future reports or create report/hash cycles.
- Explicit omissions: component/engine/full metadata/package/SDK/tool/native825/build/app/cache payload trees. Their current validation belongs to the primary admission/outcome reviews, documentary in this offline packet. The reusable reader must not claim to revalidate omitted payloads or replay JS/producer/logger/guards.

A future stdlib-only reader/analyzer opens only copied relative paths; absolute originals are documentary labels. Pin the exact manifest, enforce bounds before reads, SHA/length, safe paths, exact file/directory membership, nlink1/no aliases and physical current read bookends. Preserve historical modes/inodes and nanosecond timestamps as documentary decimal strings; allow normal Git 0644/0755 checkout modes without rewriting historical claims. Authenticate native capture completeness before marker parsing, the fixed ten-row order and source-role map, and all retained raw failure/unattempted states. It must not import/evaluate copied Source, call a helper/guard, discover PIDs, send signals, or access a target/original path. Root/C can independently replay only this DATA reader after its Source review; this note runs no check.
