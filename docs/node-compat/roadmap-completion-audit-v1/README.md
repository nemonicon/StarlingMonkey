## Dependencies after the current work

1. **Close current correctness/cost/acceptance work without changing its meaning.** The [common composition](../../../tests/node-compat/foundation-classic-streams/production-adoption-v1/common-byte-composition-root-results-v1.json) and [actual peer review](../../../tests/node-compat/foundation-classic-streams/independent-common-byte-stock-and-composition-results-review-v1/README.md) preserve the original raw-1 parent and all per-arm source origins. A separate reviewed timing phase is still required:42 calibration plus126 timed workers, unchanged pilots/budgets/orders/warmups/samples and no clipped failures. Review the final observations, RSS/size/cost counterexamples and implementation decision, then archive/accept only the explicitly proved classic scope. The new timing admission source is not a timing pass.
2. **Complete zlib validation through the genuine bootstrap, not fabricated prior runtime proof.** All three [native350 reviews](../../../tests/node-compat/foundation-zlib/native-v4-validation-bootstrap-root-review-v1.json) are available; metadata backend proof is still false/null/null. Current61 Node codec cases belong to Phase4. They do not validate consumers or classic bridges. Disabled-zlib module denial, selected RuntimeOnly/HTTP regressions, operational admission and a release checkpoint remain separate if those variants are selected. Six one-shot codecs do not close async/streaming/Brotli or old native CompressionStream lifetime gaps.
3. **Advance consumers in two honest steps.** [Isolated text/JSON metadata-v2](../../../tests/node-compat/foundation-stream-consumers/metadata-v2/component-results.json) already has native TextDecoder component evidence (18 differential/12 profile groups, two retained calls, fresh Wasmtime and11 init cases), but `installed:false`. Rebase/replay and install a finite optional consumer contract with classic and selected Web inputs, aliases/CJS/OFF/snapshot/host gates. Keep arrayBuffer/buffer/blob refusals until [Blob/File ownership and semantics](../../../tests/node-compat/foundation-stream-consumers/blob-integration-candidate/README.md) are integrated and tested. Parts must remain mutable references until final constructor conversion. Fix MIME/endings/coercion, File name/time policy, Promise order, native-memory accounting and stream cancellation/lifetime; the old304-input future runner cannot admit a changed342/350 source by projection.
4. **Repair lifecycle ownership before exposing public scheduling/ALS or reuse.** The [reset design](../../../tests/node-compat/foundation-scheduler/reset-design-v1/README.md) identifies seven task kinds and concrete unresolved timer/body-task ownership. New code must handle admission/rollback, traced cancellation batches, exactly-once resource/interest release, bounded job/finalizer settlement and late completions. [Async-context probes](../../../tests/node-compat/async-context/README.md) demonstrate isolated models, not production propagation through real timer/HTTP/FS/socket completions. Capture per-resource context/owner at actual APIs, restore on every exit and prove fresh request epochs. Do not wrap Promise.then, reset counters to hide leaks, or execute known unsafe old reset paths.
5. **Then close crypto and independently selected standard capability profiles.** Preserve pure-profile import pruning, exact0.2.10 allowlists, host-denied behavior and same-byte portability. TLS needs an explicit guest stack/trust/time/socket policy; HTTP HTTPS transport does not implement Node TLS. Process spawning/IPC/workers/V8/Inspector/POSIX signals remain deliberately unavailable under the selected interfaces. Such limits do not require inventing host services to declare the bounded profile complete.
